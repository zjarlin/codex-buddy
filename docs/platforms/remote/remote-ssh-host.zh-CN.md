# 通过 SSH 使用远程电脑上的 AI 编程工具

Web 控制台的「远程连接」（`#remote-connections`）也提供同一套连接管理、安装、更新、修复和卸载功能；需要本机已通过 codexhost 启动 Codex Desktop。参见[控制台说明](../../operations/codexhost-console.md#远程连接)。

你可以在本机的 Codex Desktop 中，使用另一台电脑上已安装并登录的 Claude Code、Pi 等 Harness（AI 编程工具）。项目和工具都在远程电脑上运行，你在本机查看回复、发送消息和操作会话。

## 开始前需要准备什么

- **本机**：安装 Codex Desktop 和 codexhost，并能打开 Codex 的「设置 → 连接 → SSH」。
- **远程电脑**：使用 Mac 或 Linux，已开启 SSH，并安装 Node.js、npm 和 Codex CLI。目前不支持将 Windows 作为远程电脑。
- **要使用的工具**：已在远程电脑上安装并登录，例如 Claude Code。
- **连接信息**：远程电脑的 SSH 地址，例如 `用户名@电脑地址`。如果连接需要指定端口或私钥文件，也请提前准备好。

建议先将本机 codexhost 更新到最新版本，再按下面的步骤安装远程端。

## 第一步：确认 SSH 可以登录

先在本机终端通过 SSH 登录一次远程电脑，并确认电脑身份。页面使用已有的 SSH 密钥或 SSH 别名，不会弹出密码输入框。

远程电脑需要已经安装 Node.js、npm 和 Codex CLI，并允许当前用户通过 npm 安装软件。Node.js 需为 22.19 及以上的 22.x 版本，或 24.x。安装时会加载用户的交互式登录 shell，包括已配置的 nvm 等版本管理器。已有安装优先使用 codexhost 记录且仍可执行的 Node 路径；如果该版本不受支持，需要先更新它再维护远程服务。如果远程电脑是 Mac，使用 Claude Code 时还需要保持该电脑的桌面用户已登录。

## 第二步：添加 SSH 连接

1. 在本机通过 codexhost 启动 Codex Desktop。
2. 打开 **codexhost 设置 → 远程连接**，点击「添加连接」。
3. 填写连接信息：
   - **名称**：给这台电脑起一个容易识别的名字，例如「公司电脑」。
   - **SSH 地址**：填写 `用户名@电脑地址`，也可以填写已有的 SSH 别名。
   - **端口、私钥路径**：仅在你的连接需要时填写，否则留空。
4. 点击「保存」后连接。原生 Codex 使用官方 SSH 与 app-server，不要求安装远端 Buddy。外部 Harness 需要远端已有兼容的 Host。
   - Buddy 与上游 codexhost 是独立发行线；Buddy 不把本机版本号交给 npm `@codexhost/cli` 安装器。
5. 显示「已连接」后，在 Codex 中打开远程电脑上的项目。

如果你已经在 Codex 中添加过 SSH 连接，这里会直接显示，不用重复添加。两处的连接设置共用，修改后也会同步显示。

来自 SSH 配置文件的连接，可以在这里修改名称。其他详细信息请修改本机 SSH 配置，或到 Codex 的「设置 → 连接 → SSH」查看。

## 第三步：选择工具并开始使用

在远程项目的输入框中，通过 **Agent / Model** 选择器选择要使用的 Harness 和模型，然后像平时一样发送消息。

本地项目和远程项目可以同时使用，各自显示对应电脑上可用的工具和模型。

如果只使用 Codex 自带的远程编程功能，不使用其他 Harness，就不需要在远程电脑上安装 codexhost。

### 图片与文件附件

外部 Harness 继续接收文字及文件路径，不通过各 Harness 的专用图片接口发送。普通文件沿用 Desktop 原生上传和远程路径引用；能否读取文件、理解图片或解析其格式，由 Harness 的工具及所选模型决定。

对于远程外部会话的普通发送（包括本地队列自动发送），若 Desktop 只提供了内嵌图片、尚未把完整图片路径写进消息，codexhost 会调用**同一远程连接的原生附件存储**，等待保存成功，再把远程路径补入文字。已有完整原生图片路径时不重复上传。本地会话和原生 Codex 会话不变；「调整方向」仍保留拒绝非文本输入的现有限制。

补存附件使用 Desktop 的 `$CODEX_HOME/attachments/` 目录和原生管理机制，不另建 SSH 上传通道或 Host 附件库。原生路径仅部分可用时，无法可靠对应每张内嵌图片，因此会补存全部内嵌图片，不按顺序猜测缺失项。补存上限为 20 张、单张 20 MiB、合计 32 MiB（解码后的图片数据）；无效数据、缺少原生保存接口、上传失败或连接被替换时不会继续发送该消息。发送结果不明时保留已上传文件，不自动重发。

该绑定依据 Desktop 26.930.31730 的附件存储与请求接口；Desktop 更新后需核对兼容性。

## 日常管理连接

在「远程连接」页面中，你可以编辑连接信息、断开连接或移除不再使用的连接。

- **断开**：不再自动连接这台电脑；远程已开始的任务仍可继续运行。需要使用时，再点击「连接」。
- **移除**：从连接列表中移除这台电脑，不会删除远程文件或会话。

## 更新远程端

页面分别显示已安装版本与运行中版本。文件已更新但进程仍旧时，可点击「重启并连接」；连接、重启、修复与卸载都需要用户主动操作，不随桌面升级自动执行。重启或修复可能中断正在运行的任务。

Buddy 桌面通过自己的 GitHub Release 更新；上游 npm `@codexhost/cli` 不属于 Buddy 发行线。版本号不能跨发行线比较。Buddy 当前不提供通过该 npm 包安装或升级远端的按钮，也拒绝相应安装请求，避免误装上游或使用不存在的 Buddy npm 版本。保留现有远端的状态查询、已安装版本重启、修复和卸载。

维护上游远端时，应按照上游发布说明独立选择版本；不要用 Buddy 桌面版本号作为 npm 版本。Buddy 远端源码变更需要构建并安装对应平台产物，更新桌面包不会把这些代码传到远端。

## 指定版本从源码测试

`npm start <版本>` 只改变本次源码启动的版本标识，不改变发行来源，不启用上游 npm 安装，也不会上传本地代码。原生 Codex 的会话恢复仍可通过官方 SSH 完成；外部 Harness 的原生会话、权限与执行需要对应 Harness 及 Host。

## 在两台电脑上查看同一个会话

如果远程电脑也安装了 Codex Desktop，可以在那台电脑上通过 codexhost 启动它。两端使用相同版本的 codexhost，并确保远程桌面登录和 SSH 连接使用同一个用户账号。

从 SSH 项目中创建的外部 Harness 会话会自动出现在另一端，首次出现可能需要几秒。两边都能查看消息、生成中的回复和工具操作，也都可以发送消息、中断任务或回答审批。

使用时注意：

- 任务运行中追加消息，请使用插入功能；另开任务可能提示忙碌。
- 两边同时回答同一个审批或提问时，以先处理的回答为准。
- 断线后重新打开会话，可以查看期间产生的内容。如果不确定一条消息是否发送成功，先查看记录再决定是否重发。

此功能适用于从 SSH 项目中创建的外部 Harness 会话。其他本地会话和 Codex 自带的会话仍按原有方式使用。

## 遇到问题怎么办

| 遇到的情况 | 可以这样处理 |
| --- | --- |
| 通过 SSH 未检测到 Node.js、npm 或 Codex CLI 中的某一项 | 按错误中点名的工具，在远程电脑上安装，或将已安装工具加入登录 shell 的 PATH 后重试。该提示不能断定工具未安装。Codex CLI 是命令行工具，远程无需安装 Codex 桌面端。 |
| 连接失败，或连接后很快断开 | 先确认 SSH 可以登录，再点击「重新检测」。原生 Codex 无需远端 Host；外部 Harness 请核对已有 Host 的安装来源和兼容性。 |
| 看不到想使用的 Harness | 在远程电脑上确认工具已安装并登录，然后在 codexhost 的「连接」页面点击「重新诊断连接」。 |
| 无法读取远程版本，或提示版本过旧 | 确认远端安装来源；不要把 Buddy 版本传给上游 npm。 |
| 更新失败 | 确认发行来源与安装版本；Buddy 不执行上游 npm 升级。 |
| 另一台电脑看不到同一个会话 | 确认两端都通过 codexhost 启动、版本相同，远程桌面与 SSH 使用同一用户。使用自定义数据目录时，两种启动方式也要保持一致。 |
| Mac 上安装失败 | 确认远程 Mac 的桌面用户已登录，再执行 `codexhost remote install`。 |

## 停止或卸载

在连接卡片中点击「卸载远程服务」。确认后，会关闭此连接的自动连接、停止远程服务并移除远程接入配置；Mac 上还会卸载配套的 Harness 后台服务。SSH 连接记录、项目文件和会话数据保留，之后可重新安装服务。卸载会中断正在进行的远程会话。

默认保留 codexhost 软件包。勾选「同时卸载 codexhost 软件包」会在服务卸载成功后，再卸载远程电脑的 npm 全局 `@codexhost/cli`，不会卸载 Codex CLI、Node.js 或其他 Harness。勾选前请确认远程桌面端不再需要通过该软件包启动。安装位置与当前 npm 不匹配时，软件包卸载会在停止服务前被拒绝；可改为仅卸载服务，或在远程电脑上手动卸载软件包。软件包卸载失败时，页面会明确提示远程服务已卸载，并允许重试。

不再使用远程端时，在远程电脑的终端执行：

```bash
codexhost remote stop
codexhost remote uninstall
```

停止服务会中断正在进行的会话。如果只是暂时断开连接，使用页面中的「断开」即可，不需要卸载。

## SSH 功能归属

模型目录和探测、Auto Router、自动会话推荐、中断会话恢复、Git 与文件操作、会话导入及已加载会话列表使用当前 SSH Host。远端 Provider、System One 和 Harness 的配置与登录留在远端；不会用本机凭据代替。会话导入后及打开已有推荐会话时保留原 Host，切换连接后不会把旧结果提交到另一台机器。

Git 侧栏的「共享项目」按当前 SSH Host 读取远端 Codex 原生项目与会话索引，不读取或返回远端 `auth.json` 中的 API Key。同步后可在「共享项目」中勾选项目并通过远端原生 `project/import` 恢复项目及其 Thread 归属；其他身份同步过的同一主机项目也会出现在列表中。凭据和原始会话始终留在远端，本机只保存投影快照。详见 [SSH 主机共享项目](../../product/remote-shared-projects.md)。

基础 Git 操作也支持原生 SSH 服务：远端明确不提供 Git RPC 时，本机 Buddy Host 使用 Desktop 已保存的 SSH 连接，在远端执行 Git。状态、暂存／取消暂存、手动提交、推送、同步、子模块、关联仓库目录浏览和 AI 提交消息生成都无需远端安装 codexhost；目录选择返回的是该 SSH 主机上的路径。AI Worker 在远端读取 Codex 配置和认证、调用远端 Provider 并读取远端 Git diff；凭据、文件和上游错误详情不离开远端。该通道的关联仓库记录按连接保存在本机。连接或操作失败不会换通道再次执行。详见 [Git 工作区](../../product/git-workspace.md)。

官方 Codex 会话菜单的“从终端打开”在 Desktop 所在机器打开所选终端，使用 Desktop 已保存的 SSH 连接，再以远端工作目录、Codex 可执行文件和 CODEX_HOME 执行 `codex resume`。远端无需图形终端；本机需有 SSH 客户端。“在 VS Code 中打开”在本机使用 Remote SSH 打开远端目录；需要 VS Code Remote SSH 扩展。单独指定密钥文件的连接应先配置 SSH 别名，确保 VS Code 使用同一密钥。

终端偏好、Desktop 更新和桌面应用入口属于本机。外部 Harness 保留自身原生能力，不能用 Codex CLI 恢复。远程 Windows 仍不受支持。

`npx -y codex-buddy sync` 只同步模型配置，不会替换持续运行的原生服务。如果配置目录已有 `auto`，但菜单缺失或扩展接口不可用，需要在现有任务结束后启动远程 Buddy Host 并重新连接。运行中的任务应先完成，避免服务切换中断执行。

如果只是希望本地项目在 Desktop 重启后不中断，不需要把工作区移到 SSH 主机，可使用[本地常驻 Host](../../product/persistent-local-host.md)。
