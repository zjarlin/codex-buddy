# 多供应商配置与故障接续

Desktop 顶部的「多供应商配置」按钮和设置页的同名入口提供执行 Host 选择、自动故障接续开关、备用供应商管理、优先顺序和最近成功上游。主供应商来自该 Host 的原生 Codex 配置，备用供应商由用户填写完整 API Base URL、独立 API Key 和可选的备用模型，不预置特定服务地址。

页面分别展示开关状态与接续条件：Host 运行时未就绪、没有已接入的主供应商、没有启用且已保存密钥的备用供应商时，会明确提示尚未就绪。主、备用行显示最近失败类型、HTTP 状态码和冷却截止时间；最近成功请求显示供应商名称与时间。这些是当前 Host 进程的请求记录，点击「刷新状态」读取，不发起模型探测或后台轮询。

同一页面可以并列配置多个网关（例如两台各自运行 sub2api 的机器），每行独立保存地址、密钥与备用模型。「停用」只让该网关退出接续顺序，配置、密钥与已拉取的模型目录都保留；只有「删除」才移除它。两者是界面上两个不同按钮，不复用同一次确认。

## 生效范围

本地与远程开发 Host 共用同一套请求代理。每个 Host 独立保存配置和凭据；在页面中选择对应 Host 后配置。未升级、未连接或不支持该方法的 Host 会显示错误，不能用本机配置冒充远端已接入。

代理覆盖当前运行时启动时已配置的自定义 Responses 供应商。新建会话与恢复的已有会话都保留原生供应商身份、历史、工具与权限，模型推理失败时才按备用顺序尝试其他上游。ChatGPT OAuth 默认供应商及外部 Harness 自有请求链路不在此范围内。页面逐项显示主供应商是否已接入；安装新版 Host 后需要由该新版运行时承载会话。

备用供应商的新增、编辑、删除、排序和启停从下一次模型请求开始生效，不重启 Host，也不中断正在返回的响应。修改原生 `config.toml` 的主供应商定义属于原生运行时配置变更，页面会将未接入的新定义标为待接入，不宣称已热更新。

## 网关模型目录

「拉取模型」直接请求各网关的 `/v1/models`（Base 写成带或不带 `/v1` 都能解析），把返回的模型 id 存进该网关的目录；不传网关即同步全部已启用且已保存密钥的网关。多个网关的目录在页面底部合并展示：**同名模型只出现一行**，并列出提供它的网关名称。单个网关失败（连接失败、超时、非 2xx、非 JSON、空列表）只影响它自己，页面按网关列出错误，并保留该网关上一次成功拉取的目录。

模型目录是只读快照，用途是让人看清「哪个网关提供哪些模型」以及据此填写备用模型；它不参与 Host 的选模，也不改动网关内部的账号调度与去重——账号池的同步与去重仍由每个网关（sub2api）自己负责。拉取不发起付费推理请求，也不在后台轮询。

## 故障处理

- 网络连接失败、首字节超时、HTTP 408/429/500/502/503/504：尝试下一个已启用的备用供应商。
- 上游失败后冷却 30 秒；冷却期间后续原生请求可直接使用其他候选，期满后再次尝试主上游。
- 编辑备用地址、密钥或模型后，旧配置的故障记录与冷却不再作用于新配置，下次请求可直接使用它。
- HTTP 400/401/403/422 等参数、认证或权限错误直接返回，不自动换供应商掩盖错误。
- 最后一个候选的 HTTP 错误保留其状态、响应内容与 `Retry-After`，不会统一替换成泛化的 503。
- HTTP 200 的未压缩 Responses 事件流仍检查终态：`response.failed` / `error` 不记为成功；明确的限流、服务端暂时故障，以及没有完成终态便结束的流，会冷却该上游。鉴权、参数及无法确定类别的事件错误显示为失败但不触发冷却。`response.incomplete` 是有效终态，不因达到输出限制而换供应商。事件只作有界旁路观察，原响应字节照常转发，已返回的流仍由原生 Codex 决定是否重试。
- 已交付部分内容后断流：结束该响应并冷却故障上游，由 Codex 原生重试决定下一次请求。Host 不拼接不同上游的流、不重发用户消息、不重新执行工具。原生重试耗尽后的失败仍明确显示，不能保证所有中途故障无感续接。
- 带 `previous_response_id` 的请求不能跨上游续接，代理不会向另一供应商传递私有响应 ID。受管自定义供应商使用 HTTP Responses，关闭其上游 WebSocket 能力，保持原生完整上下文请求路径。
- 换供应商时**会话标识跟随请求一起过去**：`x-opencode-session`、`session-id`、`session_id`、`conversation_id`、`x-session-id`、`x-session-affinity`、`x-conversation-id`。这些描述的是「同一段对话」，不属于某个上游的私有状态。OpenCode Go 自 2026-09 起要求每次上游调用带 `x-opencode-session`，缺了会直接返回 400 `MissingSessionID`，因此换成同样接 OpenCode 的备用网关时不能把它们剥掉；保留它们也让备用上游继续命中同一段 prompt cache。其余客户端头（认证、Cookie、组织标识、轮换型请求 ID）仍不转发。

备用供应商须兼容 Responses 和原生工具调用格式；模型栏留空保留原模型 ID，填写后仅替换备用请求的模型字段。模型须能容纳当前上下文，代理不翻译工具协议或伪造不支持的能力。配置不触发付费模型测试。

## 配置与隐私

配置保存在所选 Host 的 `$CODEX_HOME/provider-routing.json`，默认 Codex Home 为用户目录下的 `.codex`。同一份文件是唯一事实来源：界面原子写入，代理每次请求重新读取；外部编辑后点击「刷新状态」即可更新界面，无需重启。每个网关记录还带有该网关最近一次拉取到的模型目录与拉取时间；保存名称、顺序或开关不会覆盖它，改动端点会清空它。新文件权限为 `0600`。文件不存在时兼容读取旧 `emergency-provider.json`；首次保存后只读取新文件，删除备用项不会重新导入旧值。表单有未保存修改时，切换 Host 或替换编辑项前会提示；成功删除正在编辑的供应商后会清空表单。

启用自动接续表示允许会话上下文发送到选中的备用供应商。每个备用项使用独立密钥，主上游的 Authorization、Cookie、组织标识、自定义认证头及查询参数不会转发给备用项。更换备用端点时须重新填写 API Key；只修改名称、模型或开关可留空保留已有密钥。配置快照不返回密钥，日志不记录请求内容或凭据。

代理只监听本机回环地址，每次运行使用随机访问路径令牌，拒绝带浏览器 Origin 的请求。原始主供应商端点留在原生配置中，临时代理地址只通过启动参数注入；关闭一个 Desktop 客户端不会关闭其他客户端共享的代理。
