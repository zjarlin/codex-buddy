# 手机扫码控制

手机浏览器通过同一局域网连接本机 Host，扫码完成一次授权，之后用自己的凭据读取会话、发送消息并处理审批。本功能只提供终端控制，不复用团队用量或 Project Sync 的配对授权。

## 连接模型

- 电脑上的 Host 在 `0.0.0.0` 上监听一个随机端口，但仅在用户第一次生成配对二维码时启动。未请求配对时不会开放该端口。
- 手机与电脑必须处于同一局域网。页面由电脑直接提供，默认不支持跨 NAT、公网端口转发或 4G 直连。
- 二维码只携带一次性 invite，不携带长期 token。invite 5 分钟内有效，只允许兑换一次。
- 兑换成功后，手机获得只属于该设备的 token；Host 只保存 token 的 SHA-256 摘要，不保存明文。
- 每台手机有稳定的 `clientId` 和可编辑名称，Host 通过自己的连接通道区分 Desktop、Console、Mobile 与 Remote，不依赖 User-Agent。
- 最多配对 16 台手机。连续 30 天未使用会自动过期；在 Console 撤销后，该设备的全部 WebSocket 立即关闭。

## 安全边界

- 手机页面由本机通过局域网明文 HTTP 提供。只应在可信 Wi-Fi 上使用；能截获该流量的人可能读到会话内容。不要在共用或借用的浏览器上配对。
- 页面要求 `Host` 与 `Origin` 都属于同一监听器允许的本机局域网地址；配对请求有每 IP 限流和请求体上限；响应带 `no-store`、`nosniff`、`DENY`、CSP 等头。
- WebSocket 首帧必须是配对 hello；未认证连接在 10 秒内未发送 hello 会被关闭。
- 手机 JSON-RPC 白名单只放行会话读取、Turn 启动/插入/中断、模型与账号读取，以及 Turn 产生的审批/问答应答。手机只能回复本连接实际收到的 Host 请求，不能注入原生响应或通知。配置修改、删除、Git 写入、文件写入和 Host 私有方法仍只在 Desktop 与控制台可用。
- 服务端还会过滤 Host 发出的 server request：只有命令审批、文件审批、权限审批、工具问答和 `mcpServer/elicitation/request` 会到达手机。认证令牌刷新、证明生成、时间读取、工具调用等请求不会发送给手机，也不接受手机的伪造回复。
- 手机可以处理命令/文件的“允许一次”“本会话允许”“拒绝”，以及权限审批的“允许本次 Turn”“拒绝”。权限审批必须由用户明确确认，不会在手机端自动授权。
- 撤销会删除 token 摘要并断开该设备的全部连接。重新配对需要新的二维码。
- 传输断开会停止接收该手机的输入，但已启动的 Turn 可以在电脑上继续运行；撤销设备和关闭监听器则会请求终止该会话。

## 部署与开源

- 源码、构建脚本和发布流水线继续以仓库现有的 LGPL-3.0-only 发布；手机页面随 `renderer-extension` 一起构建，随安装包和 npm 包发布。
- 官方不需要托管用户的控制页。页面与 Host 在同一台电脑上，二维码指向该电脑的局域网地址；用户的凭据、会话和 Thread 数据不经过官方服务。
- 即使未来提供固定域名，也应当只托管静态前端或加密中继，不能托管用户会话、凭据或 Thread 数据；这不会改变代码的开源许可。
- 用户可完全离线自部署：从源码构建、使用安装包或 npm 包都能获得同一份手机页面，不需要官方账号或云端服务。

## 操作方式

1. 在电脑打开 codexhost Console，进入“手机控制”。
2. 点击“生成配对二维码”，用手机相机扫码。
3. 在手机上填写设备名称并确认配对。
4. 配对后即可查看会话列表、继续已有会话、新建会话、发送消息、停止 Turn，并处理审批或问答。新建会话使用默认 Codex 路由；已有外部 Harness 会话可以直接继续。
5. 不再使用时，在 Console 的“已配对手机”中撤销；设备上的 token 会立即失效。

## 已知限制

- 手机页面需要电脑保持运行且与手机网络互通；电脑休眠、切换网络或防火墙拦截都会导致断线重连失败。
- 手机端只保留当前浏览器本地存储中的设备凭据；清除站点数据后需要重新扫码配对。
- 手机端每次显示一个待处理交互，其余交互按到达顺序排队；在电脑端已处理的交互会从队列移除。
- 手机新建会话目前只使用默认 Codex 路由和最近会话的工作目录，不提供 Harness、模型或工作目录选择器；已有外部 Harness 会话可以直接继续。外部 Harness 的共享多选问题仍通过 Desktop 处理，手机端尚未接入 `codexhost/thread/questions/list` 与 `codexhost/thread/question/respond`。
- 跨 NAT 不属于默认能力。如果要支持，应另设加密中继，并单独评估身份、授权与撤销语义。
