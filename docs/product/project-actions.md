# 项目菜单

## 项目快捷操作

每个已渲染项目在名称旁提供一个配置按钮。配置表单可绑定内网 URL、公网 URL，以及 `start`、`restart`、`stop` 三个本机脚本路径。URL 仅允许 `http` 或 `https` 绝对地址，不能携带用户名或密码；脚本必须是绝对路径的 `.sh` 或 `.py` 文件。至少存在一个 URL 或脚本才保存绑定，删除绑定会清除该项目的全部快捷操作。表单不提供 Prompt 编辑入口；历史保存的 `binding.prompt` 仍然生效，并在保存其他字段时原样保留。绑定还可包含任意数量的自定义脚本：每项有界面显示名称 `name`、URL 安全的稳定标识 `id`（字母、数字、`-`、`_`，不能占用 `start`/`restart`/`stop`）和 `.sh`/`.py` 绝对路径 `path`。表单内可逐行添加、删除自定义脚本；新行未填写名称与路径时忽略，填写名称后自动分配 ID，已有 ID 在编辑时保持稳定。标题栏与项目行的动作组按“启动、重启、停止、自定义顺序”执行，自定义脚本使用通用终端图标。保存后，动态生成的 Prompt 任务会携带现有自定义脚本清单，并允许 AI 扩展 `binding.customScripts`。配置页只读展示本机 Host 实际读取的 `project-tools.json` 绝对路径，便于把同一路径交给 AI 回写。

项目标题显示配置按钮、已绑定时可见的 Prompt 按钮、一个主要脚本动作和“更多操作”按钮；主要脚本动作按启动、重启、停止顺序取第一个已绑定脚本。其余 URL 与其他脚本动作放在“更多操作”中。所有图标带有包含项目名、动作和完整 URL/脚本路径的原生悬浮元数据；“更多操作”菜单同时展示每项说明。访问地址窗口使用 `noopener,noreferrer`。脚本动作由本地 Host 直接执行对应脚本，不创建 Thread、不提交模型请求，因此不消耗 token；执行状态在图标上显示，结果、错误与输出摘要通过状态提示反馈。

Prompt 按钮调用项目自身的“新建会话”入口，等待目标项目的新草稿出现并确认运行目录后，把保存的 Prompt 填入 Composer 并使用 Desktop 原生发送按钮提交。保存的 Prompt 为空时，按当前项目绝对路径、精确 target 和 Host 元数据路径动态生成脚本制作任务，要求 AI 创建并验证启动、重启、停止脚本，再以原子方式合并写回元数据。不会覆盖已有其他草稿；发送按钮不可用、草稿在发送前变化或发送后未清空时保留草稿并显示错误。新会话入口、目标输入框或元数据路径无法确认时不猜测目标。

配置表单直接使用 Host 预取并镜像到本地的最新绑定打开，元数据路径在打开时已确定，不再每次点击都重新读取 Host 文件。脚本以自身所在目录作为工作目录，由 Host 使用 `bash` 执行 `.sh` 或可配置的 Python（`CODEXHOST_PYTHON`，本机默认 `python3`）执行 `.py`，并把标准输出和错误写入 `${CODEXHOST_DATA_DIR}/project-script-logs/`（默认 `~/.codexhost/project-script-logs/`）。脚本继承 Host 环境，并收到 `CODEXHOST_PROJECT_ACTION`、`CODEXHOST_PROJECT_ID` 和 `CODEXHOST_PROJECT_LABEL`。停止脚本可以在启动/重启脚本形成独立进程组后结束对应服务；Host 不会把脚本输出解释为服务健康状态。

绑定按项目种类、Host ID 和项目 ID 保存到 `${CODEXHOST_DATA_DIR}/project-tools.json`（默认 `~/.codexhost/project-tools.json`），项目重命名后仍保留，不同 Host 互不串用。Host 每次读取都重新解析文件，因此 AI 或其他工具直接修改文件后无需重启 Host。Renderer 的 `localStorage` 键 `codexhost.project-tools.v1` 仅作为同源窗口镜像和迁移来源；Host 文件是持久事实源。脚本执行请求只携带目标项目身份和动作，路径始终取自 Host 已保存的绑定，Renderers 不能临时传入任意脚本路径。

本机项目省略号按钮的下拉菜单在“在 Finder 中显示”（或系统文件管理器入口）之后提供“复制绝对路径”“在终端中打开”和“用 VS Code 打开”。保留现有置顶、编辑、归档和移除操作；远程项目不显示这些本机入口。系统原生右键菜单保持现有行为。

复制使用 Desktop Renderer 的剪贴板写入系统剪贴板，并保留完整绝对路径。终端与 VS Code 通过本机 Host 请求启动：终端复用用户已选择的终端类型，在项目目录启动交互式 shell，不续接 Codex 会话；VS Code 使用 `code --reuse-window <path>`，在 Windows 上同时识别 PATH 中的 `code` 与常见安装目录。启动失败在界面中显示，可重新点击尝试。

## 项目分类 Tab

项目列表增加分类栏与“配置项目 Tab”按钮，保留原生“全部 / 进行中”等状态筛选；两者叠加生效。首次使用预置“公司的项目”（名称以 `remote_company` 开头）、“个人的项目”（名称以 `remote_zjarlin` 开头）和“不常用”（默认无前缀，手动移入低频项目）。“项目”分类只显示没有归属 Tab 的项目；手动移入或按前缀匹配到 Tab 的项目仅在对应 Tab 显示，不再重复出现在“项目”中。当前分类没有项目时显示空态提示。

配置表单支持新增、重命名、删除与调整 Tab 顺序。每行一个名称前缀，区分大小写，任意前缀匹配即可；多个 Tab 匹配时，顺序靠前的生效。前缀留空的 Tab 仅用于手动分类。名称不能为空或重复。保存后立即生效；取消或 Escape 丢弃草稿。删除所有 Tab 后不会重新添加预置规则。旧版非空配置升级时补充“不常用”，保留已有规则、手动归属和选择；同名自建 Tab 不重复添加，升级后删除此 Tab 也不会补回。

本机和远程项目的三个点菜单均有“移动到 Tab…”入口，选择目标 Tab 后保存手动归属。手动指定优先于前缀规则；“按规则自动分类”清除覆盖。手动归属使用项目种类、Host ID 与项目 ID 标识，不依赖当前聊天或项目显示名，项目重命名后保留、不同 Host 互不串用。删除 Tab 会清除对应手动归属并恢复规则匹配；未匹配到其他 Tab 的项目回到“项目”，删除当前选中的 Tab 时选中“项目”。

选中某个自定义 Tab 后点击原生“新建项目”入口，新项目首次渲染时直接保存为该 Tab 的手动归属，不再先落到“项目”。选中“项目”时保持默认行为；原生创建入口标记不可用时不影响现有分类与移动操作。

配置、手动归属与选中分类由本地 Host 原子写入 `${CODEXHOST_DATA_DIR}/project-tabs.json`，未设置数据目录时使用 `~/.codexhost/project-tabs.json`，因此退出并重启 Desktop 后仍会恢复。旧版 `localStorage` 键 `codexhost.project-tabs.v1` 在 Host 尚无配置时自动迁移，之后继续作为同源窗口镜像并通过 storage 事件更新；Host 文件是事实源，不跨设备同步，不修改项目路径、远程仓库或 Thread 归属。Host 保存失败会显示错误并保留配置或移动表单。持久化文件损坏（非法 JSON，或引用了已不存在 Tab 的旧归属/选中项）时，Host 忽略其内容并按空配置启动，不再让该窗口永久报“读写失败”，下一次保存会原子覆盖该文件；权限等真实 I/O 错误仍如实上报。

Renderer 从原生已提交的项目行和菜单所有者读取项目身份，仅对已渲染项目应用分类，并随 DOM 更新重新匹配。原生分区、展开/加载更多、活动状态筛选仍由 Desktop 管理；被原生列表折叠或尚未加载的项目仍需展开。无法识别的项目行保持可见，避免 Desktop 私有契约变化后误隐藏项目。卸载扩展会移除分类栏、菜单入口和隐藏标记，恢复原生列表。

“最近”分区在打开 Desktop、分区重新挂载和切换项目分类 Tab 时默认收起，用户仍可点击原生标题手动展开。普通列表刷新、项目行重绘和重复点击当前分类不会再次收起；切换到其他分类后恢复收起。折叠通过 Desktop 原生按钮执行，沿用原生状态与持久化，不改变各项目或置顶、未读等其他分区的展开状态；无法确认原生分区标记和按钮状态时保持原样。卸载扩展后停止自动折叠，保留原生当前状态。

## 项目 Tab 搜索

Tab 条右侧提供“搜索项目 Tab”入口，侧栏内按 `/` 也可打开。搜索按 Tab 名称做大小写无关的模糊匹配：完全匹配、前缀、分段前缀（`_`、`-`、`.`、`/` 作为强分段边界）、连续子串、跨段子序列依次降权，同分时保持 Tab 配置顺序。`↑`/`↓` 选择、`Enter` 激活对应 Tab、`Escape` 关闭并还原焦点；中文输入法合成期间不处理确认键。搜索只切换分类，不改变项目归属、手动分类或原生状态筛选，也不占用原生 `Cmd+K` 的聊天与命令面板。

## 会话归档

会话归档沿用 Desktop 的原生流程。若本机或远程 Host 的工作区清理准备明确报错“无法确定清理工作区的账号”，则保留工作区目录，重新登记为不清理工作区，再继续原生归档；这适用于没有 ChatGPT 账号身份的 API Key 登录。其他准备错误保持原生失败行为。有账号且清理准备成功时，继续原生工作区清理流程。

## 会话文件夹

每个已渲染项目可在项目标题下建立自己的会话文件夹，用于把该项目中的原生 Thread 归类。文件夹按项目种类、Host ID 和项目 ID 隔离，同名文件夹不会跨项目共享；会话归类使用该项目的 Host Thread ID，重新渲染、项目重命名或切换项目分类后保留。文件夹只影响侧栏显示与自定义菜单，不移动、复制或改写原生 Thread、Session、工作区或归档状态。

项目标题下以可独立展开、折叠的文件夹树节点展示归类会话，不再以 Tab 或筛选条切换。原生项目行收起（项目头 `aria-expanded="false"`）时，该项目的文件夹树随之一并隐藏，展开项目后恢复原来的文件夹展开状态；其他项目的投影不受影响。未归类会话保留在项目原生列表中。右键项目或文件夹可新建、管理文件夹；右键会话可选择“移动到文件夹…”，移回“未分类”后回到项目列表。文件夹内会话入口转发到当前原生会话行，不搬动 React 管理的 DOM；仅投影 Desktop 当前已加载的会话，原生加载范围仍由 Desktop 管理。

每个文件夹行右侧提供“在此文件夹中新建会话”入口，右键文件夹同样可以发起。它调用项目自身的原生新建入口（项目行 Fiber 上的 `canStartNewThread` / `onStartNewThread`），由 Desktop 决定项目、Host、草稿配置与导航，扩展不自行拼装 `thread/start`。原生入口不可用时保持原状并提示，不猜测行为。

新建后出现的会话自动归入该文件夹：扩展记录一个待定意图，并只在新会话唯一确定时成立——点击后恰好新出现一个未提交草稿时绑定该草稿，草稿换成原生 Thread ID 且恰好新出现一个已物化会话时写入归类。同时出现多个新会话，或草稿消失后迟迟看不到新会话（超过 1 分钟）时放弃意图，避免把无关会话误归入文件夹；放弃后会话仍保留在原生列表，可右键手动移动。归类只在会话物化后写入 `thread-folders.json`；待定意图只存在于当前窗口内存，刷新即丢弃。

文件夹内会话入口复用原生行的状态语义：正在执行的会话显示转圈，失败、已取消或已中断的会话显示对应颜色的恢复图标并带状态提示，有未读结果时显示蓝点。状态只在投影时从原生行的已提交 Fiber（`statusState`）和 Buddy 恢复标记读取，不复制原生节点、不写入原生状态，也不改变原生行自身的状态显示；原生行未投影时保持无状态。状态变化随原生行重绘重建投影。

项目内右键使用扩展菜单，会话菜单中的“原生会话操作…”可打开 Desktop 原生菜单。此入口不依赖 DOM 观察器修改 Electron 系统菜单。文件夹展开状态仅在当前窗口保留；旧配置中的 selected 字段继续兼容读取，但不再控制显示。

文件夹配置与归类由本地 Host 原子写入 `${CODEXHOST_DATA_DIR}/thread-folders.json`，未设置数据目录时使用 `~/.codexhost/thread-folders.json`。Renderer 的 `localStorage` 键 `codexhost.thread-folders.v1` 只作为同源窗口镜像和旧数据引导；Host 文件是持久事实源，不跨设备同步。配置异常时保留原生会话行并显示错误，不自动覆盖损坏文件。
