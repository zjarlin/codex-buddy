# 项目菜单

本机项目省略号按钮的下拉菜单在“在 Finder 中显示”（或系统文件管理器入口）之后提供“复制绝对路径”“在终端中打开”和“用 VS Code 打开”。保留现有置顶、编辑、归档和移除操作；远程项目不显示这些本机入口。系统原生右键菜单保持现有行为。

复制使用 Desktop Renderer 的剪贴板写入系统剪贴板，并保留完整绝对路径。终端与 VS Code 通过本机 Host 请求启动：终端复用用户已选择的终端类型，在项目目录启动交互式 shell，不续接 Codex 会话；VS Code 使用 `code --reuse-window <path>`，在 Windows 上同时识别 PATH 中的 `code` 与常见安装目录。启动失败在界面中显示，可重新点击尝试。

## 项目分类 Tab

项目列表增加分类栏与“配置项目 Tab”按钮，保留原生“全部 / 进行中”等状态筛选；两者叠加生效。首次使用预置“公司的项目”（名称以 `remote_company` 开头）、“个人的项目”（名称以 `remote_zjarlin` 开头）和“不常用”（默认无前缀，手动移入低频项目）。“项目”分类只显示没有归属 Tab 的项目；手动移入或按前缀匹配到 Tab 的项目仅在对应 Tab 显示，不再重复出现在“项目”中。当前分类没有项目时显示空态提示。

配置表单支持新增、重命名、删除与调整 Tab 顺序。每行一个名称前缀，区分大小写，任意前缀匹配即可；多个 Tab 匹配时，顺序靠前的生效。前缀留空的 Tab 仅用于手动分类。名称不能为空或重复。保存后立即生效；取消或 Escape 丢弃草稿。删除所有 Tab 后不会重新添加预置规则。旧版非空配置升级时补充“不常用”，保留已有规则、手动归属和选择；同名自建 Tab 不重复添加，升级后删除此 Tab 也不会补回。

本机和远程项目的三个点菜单均有“移动到 Tab…”入口，选择目标 Tab 后保存手动归属。手动指定优先于前缀规则；“按规则自动分类”清除覆盖。手动归属使用项目种类、Host ID 与项目 ID 标识，不依赖当前聊天或项目显示名，项目重命名后保留、不同 Host 互不串用。删除 Tab 会清除对应手动归属并恢复规则匹配；未匹配到其他 Tab 的项目回到“项目”，删除当前选中的 Tab 时选中“项目”。

选中某个自定义 Tab 后点击原生“新建项目”入口，新项目首次渲染时直接保存为该 Tab 的手动归属，不再先落到“项目”。选中“项目”时保持默认行为；原生创建入口标记不可用时不影响现有分类与移动操作。

配置、手动归属与选中分类由本地 Host 原子写入 `${CODEXHOST_DATA_DIR}/project-tabs.json`，未设置数据目录时使用 `~/.codexhost/project-tabs.json`，因此退出并重启 Desktop 后仍会恢复。旧版 `localStorage` 键 `codexhost.project-tabs.v1` 在 Host 尚无配置时自动迁移，之后继续作为同源窗口镜像并通过 storage 事件更新；Host 文件是事实源，不跨设备同步，不修改项目路径、远程仓库或 Thread 归属。Host 保存失败会显示错误并保留配置或移动表单，读取损坏配置会显示错误而不自动覆盖文件。

Renderer 从原生已提交的项目行和菜单所有者读取项目身份，仅对已渲染项目应用分类，并随 DOM 更新重新匹配。原生分区、展开/加载更多、活动状态筛选仍由 Desktop 管理；被原生列表折叠或尚未加载的项目仍需展开。无法识别的项目行保持可见，避免 Desktop 私有契约变化后误隐藏项目。卸载扩展会移除分类栏、菜单入口和隐藏标记，恢复原生列表。

“最近”分区在打开 Desktop、分区重新挂载和切换项目分类 Tab 时默认收起，用户仍可点击原生标题手动展开。普通列表刷新、项目行重绘和重复点击当前分类不会再次收起；切换到其他分类后恢复收起。折叠通过 Desktop 原生按钮执行，沿用原生状态与持久化，不改变各项目或置顶、未读等其他分区的展开状态；无法确认原生分区标记和按钮状态时保持原样。卸载扩展后停止自动折叠，保留原生当前状态。

## 项目 Tab 搜索

Tab 条右侧提供“搜索项目 Tab”入口，侧栏内按 `/` 也可打开。搜索按 Tab 名称做大小写无关的模糊匹配：完全匹配、前缀、分段前缀（`_`、`-`、`.`、`/` 作为强分段边界）、连续子串、跨段子序列依次降权，同分时保持 Tab 配置顺序。`↑`/`↓` 选择、`Enter` 激活对应 Tab、`Escape` 关闭并还原焦点；中文输入法合成期间不处理确认键。搜索只切换分类，不改变项目归属、手动分类或原生状态筛选，也不占用原生 `Cmd+K` 的聊天与命令面板。

## 会话归档

会话归档沿用 Desktop 的原生流程。若本机或远程 Host 的工作区清理准备明确报错“无法确定清理工作区的账号”，则保留工作区目录，重新登记为不清理工作区，再继续原生归档；这适用于没有 ChatGPT 账号身份的 API Key 登录。其他准备错误保持原生失败行为。有账号且清理准备成功时，继续原生工作区清理流程。

## 会话文件夹

每个已渲染项目可在项目标题下建立自己的会话文件夹，用于把该项目中的原生 Thread 归类。文件夹按项目种类、Host ID 和项目 ID 隔离，同名文件夹不会跨项目共享；会话归类使用该项目的 Host Thread ID，重新渲染、项目重命名或切换项目分类后保留。文件夹只影响侧栏显示与自定义菜单，不移动、复制或改写原生 Thread、Session、工作区或归档状态。

项目标题下以可独立展开、折叠的文件夹树节点展示归类会话，不再以 Tab 或筛选条切换。未归类会话保留在项目原生列表中。右键项目或文件夹可新建、管理文件夹；右键会话可选择“移动到文件夹…”，移回“未分类”后回到项目列表。文件夹内会话入口转发到当前原生会话行，不搬动 React 管理的 DOM；仅投影 Desktop 当前已加载的会话，原生加载范围仍由 Desktop 管理。

项目内右键使用扩展菜单，会话菜单中的“原生会话操作…”可打开 Desktop 原生菜单。此入口不依赖 DOM 观察器修改 Electron 系统菜单。文件夹展开状态仅在当前窗口保留；旧配置中的 selected 字段继续兼容读取，但不再控制显示。

文件夹配置与归类由本地 Host 原子写入 `${CODEXHOST_DATA_DIR}/thread-folders.json`，未设置数据目录时使用 `~/.codexhost/thread-folders.json`。Renderer 的 `localStorage` 键 `codexhost.thread-folders.v1` 只作为同源窗口镜像和旧数据引导；Host 文件是持久事实源，不跨设备同步。配置异常时保留原生会话行并显示错误，不自动覆盖损坏文件。
