# Spec Delta

## Purpose

让 Host 在界面内完成远端 Git 登录，并把该登录态用于所有由 Host 发起的 Git 网络操作，覆盖 GitHub、Gitee、GitLab 与其他自建主机。

## ADDED Requirements

### Requirement: 远端主机识别

系统 SHALL 从项目仓库的远端地址识别主机与托管平台，并把同一主机的多个仓库合并为一条记录。

#### Scenario: 识别已知平台
- **WHEN** 项目仓库的远端是 `https://github.com/zjarlin/codex-buddy.git` 或 `git@github.com:zjarlin/codex-buddy.git`
- **THEN** 该主机被识别为 `github.com` 且平台为 GitHub，两种传输协议归入同一条记录

#### Scenario: 保存过账号但项目已不再引用
- **WHEN** 某主机存在已保存的登录态，而当前项目没有该主机的仓库
- **THEN** 该主机仍出现在列表中，便于退出或复用其登录态

### Requirement: 登录态来源与状态

系统 MUST 区分“本产品保存的账号”“本机 gh/glab 登录态”“系统 Git 凭据助手可用”三种来源，并在未登录时明确显示为未登录。

#### Scenario: 未登录
- **WHEN** 某主机没有保存账号、没有 gh/glab 令牌、也没有可用的系统凭据
- **THEN** 该主机状态为未登录，并提供登录入口

#### Scenario: 复用本机登录态
- **WHEN** 本机 `gh` 已登录 github.com 或 `glab` 已登录该 GitLab 主机
- **THEN** 该主机显示为可用，来源标记为对应命令行工具，无需用户再次输入令牌

### Requirement: 令牌登录与保存

系统 SHALL 支持用 HTTPS 访问令牌登录指定主机，令牌只保存在 Host 本地，界面永远不读取令牌原文。

#### Scenario: 登录成功
- **WHEN** 用户提交某主机的有效令牌
- **THEN** 账号保存为该主机的登录态，若平台接口可验证则记录账号标识与验证时间

#### Scenario: 令牌无法验证
- **WHEN** 平台接口拒绝该令牌或接口不可达
- **THEN** 系统保留已保存的账号但标记为未验证，并在结果中说明未通过验证的原因，不删除账号

#### Scenario: 令牌回传
- **WHEN** 界面读取任意主机的账号信息
- **THEN** 返回内容只包含主机、平台、登录方式、账号标识与时间，不包含令牌

### Requirement: SSH 密钥登录

系统 SHALL 为 SSH 远端提供由本产品生成或复用的密钥对，并公开公钥供用户粘贴到平台。

#### Scenario: 首次查看公钥
- **WHEN** 某主机尚无本产品密钥且用户请求查看公钥
- **THEN** 系统生成新密钥对并返回公钥与指纹

#### Scenario: 已有密钥
- **WHEN** 某主机已有本产品密钥
- **THEN** 系统返回同一把公钥，不重复生成

#### Scenario: 私钥不对外
- **WHEN** 界面读取密钥信息
- **THEN** 只返回公钥、指纹与是否存在，私钥路径与内容不返回

### Requirement: 凭据自动注入

Git 工作区的推送、拉取、同步与克隆 MUST 自动使用对应主机的已保存登录态，且不修改用户的全局 Git 配置。项目清单同步等独立 Git 调用沿用系统凭据，不在本能力范围。

#### Scenario: 已登录后推送
- **WHEN** 主机已保存令牌并使用 HTTPS 远端
- **THEN** 推送与拉取成功，无需用户再次输入用户名或口令

#### Scenario: SSH 远端与已生成密钥
- **WHEN** 主机使用 SSH 远端且本产品密钥存在
- **THEN** Git 命令把该密钥作为候选身份，同时保留用户 ~/.ssh 中已有的身份

#### Scenario: 未生成密钥的 SSH 远端
- **WHEN** 主机使用 SSH 远端且本产品尚未生成密钥
- **THEN** Git 命令不注入本产品身份，用户自己的 SSH 配置继续生效

#### Scenario: 未登录推送
- **WHEN** 主机没有任何可用登录态且远端要求认证
- **THEN** 操作失败并提示在该主机登录，错误信息不包含任何凭据内容

### Requirement: 连接验证

系统 SHALL 允许用户对已登录主机发起一次验证，并返回面向用户的结论。

#### Scenario: 验证通过
- **WHEN** 该主机存在可访问的仓库且凭据有效
- **THEN** 结果说明连接成功并记录验证时间

#### Scenario: 验证失败
- **WHEN** 凭据无效、平台不可达或没有可验证的仓库
- **THEN** 结果说明具体原因，且不把失败静默当作成功
