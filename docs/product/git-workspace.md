# Git 工作区界面

左侧导航第二项为“提交”。侧栏保留分支信息、提交消息与操作区、变更／已暂存文件列表；文件和目录行高为 24px。提交消息位于文件列表上方。不提供独立 Git 日志入口。

已有会话的输入框上方始终展示主工作区的当前 Git 分支，悬停可查看工作区路径和完整分支名；detached HEAD 显示 `HEAD` 与短提交号。该信息跟随当前会话及 Host，独立于提交侧栏是否打开或选中了哪个关联仓库。新建对话保留原生分支入口。读取失败显示“Git 分支不可用”，悬停显示错误原因，不沿用其他会话的分支。

文件右侧状态沿用 Git 单字符语义：`M` 为已跟踪文件修改，`U` 为未跟踪，`S` 表示当前在已暂存列表，`!` 为冲突。暂存区的 `+` 只用于把变更加入索引，已暂存项使用 `-` 取消暂存，避免暂存项继续显示加号造成误判。

提交操作区在“提交并推送”下方提供图标按钮：托盘加下箭头的图标表示“全部暂存”，一次把全部可暂存变更加入索引；列表减号的图标表示“全部取出”，一次把全部已暂存变更取消暂存。两者只在存在对应变更且无进行中操作时可用。主操作按钮悬停时保持白字和实心背景，避免叠加通用悬停样式后出现白底白字。

面板顶部显示当前聊天对应的项目目录名，悬停显示完整路径。项目由当前可见的主对话 Composer 与当前 Host 确定，已有聊天由 Host 按任务 ID 解析工作区；新聊天直接使用原生预热发布的当前 Host 项目目录，无需先发送消息或创建任务。不使用侧栏列表中其他任务的项目。切换任务、草稿项目或 Host 时立即切换到对应缓存快照并清空旧提交草稿，读取目标工作区的状态和模型目录。没有聊天且没有选定项目时才显示“未选择项目”；草稿项目名在 Git 状态返回前即可显示，读取失败仍保留。

状态、模型目录和 AI 提交消息只更新发起请求时的任务与 Host；审查请求也按同样的上下文取消过期操作。旧项目的延迟结果不会覆盖新项目；在暂存与提交之间切换聊天时，不继续发起旧项目的提交。

## 关联其他仓库

在提交面板点击“关联仓库”，可从当前连接所在设备浏览目录并选择，也可直接输入绝对路径。原生 SSH 连接浏览的是远端主机目录，不会读取 Desktop 本机同名路径；Host 验证目录后解析为 Git 工作树根目录，子目录或符号链接指向同一仓库时去重。关联成功后自动选中新增仓库，也可用“操作仓库”下拉框切回标有“会话项目”的主仓库。

关联关系按会话主项目的真实根目录保存在该 Host 的 `CODEX_HOME/git-repository-links` 中，同一项目的其他任务和 Host 重启后均可读取。不同 worktree 分别保存。“解除”仅移除关联记录，保留文件、Git 历史和远端配置；主项目不能解除。

原生 SSH 连接使用下述 SSH Git 通道时，关联记录保存在 Desktop 本机的 `CODEX_HOME/ssh-git/<连接配置哈希>/git-repository-links`，按保存的连接配置隔离；仓库路径解析、文件内容和 Git 操作仍全部在远端执行。该记录不会自动与远端 codexhost 或其他 Desktop 同步。

选中仓库后，状态、暂存、消息生成、提交、推送、同步和子模块操作都使用该仓库；审查入口将仓库根目录交给官方审查面板。Host 对每次显式仓库请求校验关联关系，拒绝未关联或位置被替换的仓库；会话主项目下已声明的 Git 子模块工作树自动获得同等操作权限，不写入关联列表。切换仓库清空提交草稿并取消待完成的审查请求，隔离缓存和延迟请求；切换任务或 Host 默认返回对应的会话项目。关联不改变聊天执行目录或普通文件浏览器。

已初始化子模块在提交面板中形成可展开的独立仓库分组，分别展示内部文件、暂存、提交消息、提交、提交并推送和推送。父仓库的子模块行继续表示 gitlink 变更；未初始化子模块保留初始化入口。

输入框旁的“推送代码”按钮和会话结束自动 hook 处理会话主项目、已关联仓库及它们已初始化的子模块。提交面板中的“提交并推送”“推送”仍只操作当前选中的仓库。

## 加载与缓存

- 目录树默认折叠，点击目录才创建子项。进入面板不自动读取或打开首个文件差异。
- 激活聊天时分支信息立即读取 Git 状态，侧栏延迟 250ms 预热并共享同一缓存和进行中的请求；只读取当前任务或草稿项目，不批量读取文件正文。会话分支在窗口可见时每 30 秒检查一次缓存，过期后读取最新状态，重新聚焦或恢复可见时也检查。
- 当前会话目录不是 Git 仓库时，Host 返回错误后结束加载并显示“未检测到工作区”和错误原因；不会递归扫描子目录，也不会永久停留在“正在读取项目…”。项目推送工作流与之独立：主目录不是仓库但已关联子目录中的仓库时，仍按该会话目录作为项目范围执行推送。
- SSH 连接明确不支持 Git RPC 时，自动通过 Desktop 已保存的 SSH 配置执行远端 Git。其他连接缺少 Git 服务时仍显示不可用提示。状态读取失败时不继续加载提交消息模型，保留原始错误并禁用写操作；无法读取状态不显示为“没有待提交的变更”。
- 状态、提交历史和模型目录按 Host 客户端、任务或草稿目录与所选仓库隔离缓存 30 秒，并合并进行中的相同请求。预热只读取主仓库状态；打开提交操作区才读取模型目录，点击“历史”才读取提交历史。再次进入先显示已有状态，过期后刷新。缓存仅保留在当前 Desktop 进程中，最多 48 项、约 16 MiB。
- 主仓库文件和子模块脏状态共用一次 `git status` 扫描。子模块独立状态只在展开分组时加载；其等待或失败不阻塞主仓库按钮，也不重建或重复追加主列表。刷新时只重新读取已展开的子模块。切换任务、Host 或仓库后忽略旧请求的回包。
- 暂存、取消暂存、提交和推送直接使用操作返回的新状态，避免重复查询。写操作清理该 Host 的旧快照；推送后折叠侧栏目录。官方正文刷新和关闭由官方界面管理。手动刷新强制重新读取。
- 仅忙碌状态或选中文件变化时复用现有列表节点；差异展示、长文件虚拟化、语法高亮与文件编辑全部交给官方界面。
- 刷新、暂存、提交、推送、同步、子模块操作和生成消息显示按钮 loading 和 `aria-busy`，请求结束前禁用冲突操作。操作锁按 Host 客户端、任务与所选仓库保存，切换聊天再返回仍保持；成功或失败后释放，失败可重试。
- Host 将同一工作区、同一参数的进行中写请求合并为一次执行。该保护只覆盖重叠请求，不把已完成请求永久缓存为成功。
- Git 索引中的子模块缺少 `.gitmodules` 映射时，面板单独显示配置警告，仍返回文件状态、有效子模块和暂存／提交／推送结果；不自动修改仓库配置。其他 Git 错误正常报告。

## 提交、推送与拉取同步

- 操作区提供“提交”“提交并推送”“推送”“拉取并同步”。点击“AI 生成”才请求所选模型根据真实改动生成提交消息，生成后仍可编辑；打开面板和切换项目不会自动请求模型。Host 只在采集 Git 快照时占用串行队列，等待模型回复期间释放队列，其他 Git 状态读取与操作可继续。推理型模型（如 Ask 虚拟模型、DeepSeek-V4）会把输出额度先用于推理：首轮额度不足、正文为空且 `finish_reason=length` 时，Host 自动提高额度重试一次；只有模型确实耗尽额度才重试，正常空回复仍按失败报告，不会把故障伪装成等待。
- “拉取并同步”先 `fetch` 再按落后情况合入：本地无独有提交时快进，否则以 merge 合入上游，默认不变基。远端没有新提交时提示已是最新。
- 推送结束保留可见结果：返回上游且 ahead／behind 均为零时显示“推送成功，已与上游同步”；仍有领先或落后提交时显示未同步数量。提交并推送以返回的 `pushed` 状态判断是否真正推送，不根据按钮名称宣称成功。
- 推送被远端拒绝（non-fast-forward）时，Host 回带结构化 `push-rejected` 错误和落后提交数，界面提示改用“拉取并同步”，不强制推送。
- 同步产生冲突时，`git/status` 返回 `operation` 与 `conflicts`。侧栏顶部的冲突横幅列出待解决文件，并提供“解决并继续”“中止合并”；仍在冲突中的文件不计入可提交变更。
- 冲突消解由模型回合完成（见 [Buddy Auto Router](buddy-auto-router.md) 的 Git 工作流），侧栏只负责展示状态、继续或中止，不自动合并冲突内容。

## 提交历史

提交操作区顶部的“历史”按钮切换到独立历史视图，原“提交”侧栏入口仍打开变更列表与操作区。历史最多展示 200 条按拓扑顺序排列的提交，根据真实父提交绘制分支和合并连线，并显示同一提交上的所有本地分支、远端跟踪分支与标签。底部延伸线表示更早的提交未包含在本批结果中。

首次打开读取本地已有引用，不自动联网。“获取上游”显式执行 `fetch` 后更新状态与历史，可查看上游新提交；它不合并工作树。普通刷新重新读取本地状态与历史。写操作使历史缓存失效，过期请求不会覆盖当前 Host／仓库视图。

## 官方审查与文件浏览

- 官方审查依赖真实 Thread Scope；新聊天尚未创建时，点击文件会提示创建聊天后查看差异。已有聊天点击“审查”或变更文件时，转发官方 `run-command / openReviewTab`。扩展不再创建聊天区域覆盖层、差异渲染器或结果编辑器。
- 打开后，从已提交的原生标签 React 祖先读取官方 Review Tab 与当前 Thread Scope，校验 `conversationId`、`hostId` 和恢复契约版本。复用该 Tab 的 `durableRoute.restore`，不导入混淆后的 bundle 导出，不另挂 React 根，也不移动官方组件。
- 恢复参数携带官方会话的 `cwd`、Host、Thread、所选 `repositoryRoot` 和 `diffFilter`。变更列表使用 `uncommitted`，已暂存列表使用 `staged`；主项目的 `repositoryRoot` 为 `null`。差异、状态与文件正文由官方 Git 和文件服务自行读取，不调用 codexhost 的 `git/diff`、`git/content` 或工作区读写 RPC 向官方 UI 注入正文。
- 关联仓库和子模块传入其明确根目录；恢复后校验官方 Tab 回带的仓库和比较范围。官方拒绝或无法保持该选择时提示用户，不把主仓库内容当作关联仓库展示。
- 文件行尝试通过官方 `data-review-path` 或原生文件树行定位文件。文件尚未出现在原生视图时保留已打开的官方审查，并提示在官方文件树中选择。
- 切换文件、任务、Host 或仓库、切换侧栏、刷新及销毁扩展会取消过期的打开和定位请求。已打开的官方标签页由 Desktop 管理，扩展不代为关闭。
- 文件浏览器按钮转发官方文件树按钮；未找到该按钮时使用官方 `toggleFileTreePanel` 命令。扩展调用官方“移到左侧窗格”动作，将整个文件／审查区域放在对话区左侧；面板内部的文件树位于内容左侧。读取、编辑与保存仍由官方处理，详见[工作区文件浏览与编辑](workspace-files.md)。终端继续转发官方底部面板按钮。
- 外部 Harness 的回合文件变更继续通过现有 `fileChange` 与 `turn/diff/updated` 协议投影进入官方状态；此次改动不引入第二份回合差异数据。

## 实现与验证

`renderer-git-sidebar.ts` 负责导航、列表和 Git 操作；`renderer-git-history.ts` 负责历史请求状态与父提交图；`renderer-native-workspace.ts` 负责官方工作区命令、Review Tab 契约校验、恢复和文件定位；`renderer-native-file-pane.ts` 调用官方菜单将整个文件区域放在对话左侧；`renderer-native-file-tree-layout.ts` 负责面板内文件树的左侧布局及拖拽方向适配。Host 的 Git 与文件 RPC 仍可供其他调用方使用。

Git RPC 接受互斥的 `threadId` 或 `cwd`：前者由 Host 解析，后者必须是接收请求的 Host 上的绝对路径。关联仓库和子模块继续按主项目校验；禁止同时指定两种目标，避免目录覆盖已有聊天的归属。

### 原生 SSH 的 Git 通道

参考 [VS Code Remote Development](https://code.visualstudio.com/docs/remote/remote-overview) 将工具放在工作区所在机器执行的原则，以及其 [Git 扩展在仓库 cwd 启动 Git 进程](https://github.com/microsoft/vscode/blob/main/extensions/git/src/git.ts) 的实现。codexhost 优先使用远端 Git RPC；只有明确返回“不支持该方法”时，`renderer-ssh-git.ts` 才转交本机 `codexhost/ssh/git`。网络失败、超时、提交或推送失败不会触发另一路重试，避免重复写操作。

已有会话先通过同一远端连接的 `thread/read` 解析 cwd，再转交 Host ID 和远端绝对目录；草稿直接使用当前 Host 的项目目录。本机 Host 不解析远端 Thread ID，也不访问本机同名目录。连接替换或失效会取消尚未转交的请求。

`ssh-git.ts` 从 Desktop 保存的连接读取 SSH 别名、主机、端口和密钥配置，通过系统 SSH 在远端调用 Git，复用 `GitWorkspace` 的状态、暂存、提交、推送、同步和子模块语义。协议仅允许指定 Git 方法，不接受任意命令或 SSH 选项；路径、文件正文和 Git 元数据读取也使用远端执行器。SSH 使用非交互模式与超时；Git 认证及签名使用远端环境，失败正常报告。基础 Git 操作无需远端安装 codexhost，远端须提供 Git 和 POSIX shell。

原生 SSH 通道通过固定 Worker 在远端读取 `CODEX_HOME`（默认 `~/.codex`）中的 Provider 配置和认证，列出模型并根据远端 Git 变更生成提交消息；远端 SSH 环境须可执行 Node.js 18 或更高版本。Worker 只接受这两类结构化请求，模型请求、Git 文件、凭据和上游错误详情都留在远端；本机不会读取或代用自己的 AI 账号。远端没有有效模型配置时保留空模型列表，仍可手动填写消息并提交或推送。

Host 在 `git-workspace.ts` 提供 `git/fetch`、`git/sync`、`git/merge/continue` 与 `git/merge/abort`；`git/sync` 默认以 merge 合入上游并在冲突时保留合并态，冲突内容交由模型回合消解。

`tests/e2e/renderer-git-sidebar.spec.ts` 使用浏览器夹具覆盖命令转发、原生恢复参数、远程 Host 归属、过期请求、关联仓库与子模块、状态缓存、提交与同步。夹具不等同于真实 Desktop 验收。原生恢复契约依据已保存的 Desktop 26.924.22138 bundle 核对；真实安装版本仍需验证原生标签与 Scope 的绑定，以及实际 Git／文件读取结果。

## 项目推送工作流

聊天输入框附近的“推送代码”按钮触发当前项目的提交并推送工作流，保留输入草稿。按钮显示等待、准备、运行、完成或失败状态；请求期间显示 loading，禁止重复点击。工作流沿用触发任务，在原对话中展示 Git 操作和结果，不新建任务。

默认监听 Host 的真实回合结束事件：原生 Codex `turn/completed` 和外部 Harness 的成功终态都可触发。等待 750ms 后，按 Git 工作树根目录（解析符号链接）汇总同一项目的任务；子目录聊天归到同一工作树，不同 worktree 分开处理。启动时读取会话主项目的关联清单及已初始化的递归子模块，验证真实根目录并去重，不扫描未关联的独立 Git 目录，不自动初始化子模块。会话项目目录本身不是 Git 仓库时（仓库位于会话目录的子目录），项目范围取该会话目录，仓库清单只包含已关联的仓库；不因为主目录不是仓库而判定“不是 Git 项目”。运行回合、等待审批、启动中的请求、规划、子任务和自动续接都阻止涉及同一仓库的项目启动推送；其他项目仍可继续运行。只有全部仓库均无新改动、无未完成的合并／变基、本地与上游无领先或落后提交时才跳过；干净且引用未变的 detached HEAD 子模块无需另行推送。

同一 Host 服务的 Desktop 与远程客户端共享仓库锁和终态去重；启动前分页检查原生任务列表，并汇总各连接的外部任务。自动 hook 与手动按钮共用入口，同一项目只启动一次；不同项目的仓库清单有交集时也串行执行，锁释放后唤醒等待的项目。模型准备期间若有新任务开始，回到等待状态；推送期间其他任务完成时，合并成一次后续检查，待当前工作流结束且涉及的仓库空闲后处理。手动点击时项目仍忙也会等待，无需再次点击。

检查其他活动任务时，其工作目录已删除或不再是目录的，记录诊断并跳过，不把该目录错误写入当前项目的推送状态。当前任务自身的目录读取失败仍报错；其他任务的权限或仓库读取错误不按目录失效跳过。

官方 Codex 使用当前可用的 Git 执行模型与已启用的 Git／GitHub／GitLab／PR 技能，跳过意图分类和高级模型规划；外部 Harness 沿用其原生会话配置。两条执行路径收到相同的明确仓库清单，各仓库分别生成消息、提交并推送各自分支；先推送最深层子模块，再提交并推送父仓库的 gitlink 引用，子模块失败时不发布指向未推送提交的父仓库引用。父仓库 gitlink 已变化时，即使 detached 子模块内部干净，也必须确认其提交的真实远程与发布分支，不能只凭工作区干净判定已发布。有改动的 detached HEAD、缺少远程或上游时确认真实发布目标，不能猜测分支。推送被拒时按既有 Git 工作流 fetch／merge、解决冲突、验证并重试。原生权限与审批保留，隐私模式和已知的 Plan Mode 不执行该工作流。

当远程连接只提供原生 Codex Thread、没有 `codexhost/git/workflow` RPC 时，Renderer 会将同一工作流作为当前 Thread 的原生回合执行，并按 Thread 状态展示运行、完成或失败。结构化 Git 侧栏通过上述 SSH Git 通道提供状态、暂存和独立提交操作；官方审查与文件浏览沿用 Desktop 的原生远程能力。

只对正常完成的任务新增自动请求。失败或取消不新增请求；已有等待请求会在其他任务结束后重新检查。工作流自己的终态不再次触发推送。完成后重新读取全部仓库的工作区、进行中的 Git 操作、上游及 ahead／behind 状态；任何仓库未同步、清单变化或 detached 子模块引用变化且未发布时显示失败，并列出未完成的仓库路径，可手动重试。部分成功和模型回合正常结束都不能代替全部仓库的 Git 验收。Host 启动、历史回放及只读状态检查不会补跑推送。

`CODEXHOST_GIT_AUTO_PUSH=0` 可关闭结束 hook，保留手动按钮。状态与锁保留在当前 Host 服务进程内，重启不恢复未执行的等待请求。按钮状态轮询只读取内存快照；原生任务扫描与 Git 检查在工作流触发时进行。

### 回合动作入口

新 Host 的 Composer 按钮通过统一动作注册表执行 `git.commit_push`，按钮语义仍是提交并推送；旧 Host 不支持动作方法时保留原 Git 工作流入口。回合卡片另提供 `git.commit`（提交代码、不推送）。仅提交在启动前取消本聊天尚未开始的自动推送请求，且其完成事件不触发自动推送；项目推送已经运行时拒绝启动仅提交。其他聊天的自动工作流保留原有项目协调语义。

动作入口不抢占正在执行的回合。首次启动前持久化 invocationId，同一次点击或传输重试读取原受理记录；状态未知时不自动重放。执行记录的回合完成与项目推送工作流的 Git 验收分别保留，不能用回合成功替代各仓库已同步。已进入项目工作流后的排队与锁规则沿用上文。
