# Git 工作区界面

左侧导航第二项为“提交”。侧栏保留分支信息、提交消息与操作区、变更／已暂存文件列表；文件和目录行高为 24px。提交消息位于文件列表上方。不提供独立 Git 日志入口。

面板顶部显示当前聊天对应的项目目录名，悬停显示完整路径。项目由当前可见的主对话 Composer 与当前 Host 确定，Host 再按任务 ID 解析工作区；不使用侧栏列表中其他任务的项目。切换任务或 Host 时立即清空旧项目状态、提交草稿和模型目录，再加载当前项目。没有激活任务时显示“未选择项目”。

状态、差异、模型目录和 AI 提交消息只更新发起请求时的任务与 Host。旧项目的延迟结果不会覆盖新项目；在暂存与提交之间切换聊天时，不继续发起旧项目的提交。

## 主区域内容

- 选择变更文件后，差异正文占用聊天区域。侧栏文件列表保持可操作。
- 文件正文支持“统一”“并排”“结果”三种视图。并排视图左栏显示基准版本，右栏显示当前工作区；对比块左侧的采纳按钮会把该行应用到结果版本。
- 结果视图允许直接编辑并保存回工作区；保存使用文件打开时的版本校验，文件被其他程序改动时拒绝覆盖。
- 冲突文件显示 BASE、当前和传入版本，可直接采用当前或传入内容，再编辑后保存。冲突未解决前不能从正文暂存。
- 内容视图跟随原生主对话表面的位置与大小，避开顶部栏、侧栏和已展开的底部面板。找不到主对话表面时隐藏正文。
- 点击关闭按钮或按 Esc 返回聊天；切换到项目或文件浏览器也会关闭 Git 正文。聊天 DOM 与会话状态保留。
- 成功提交后关闭旧差异；关闭、切换文件或切换会话后，过期的异步差异不会重新打开内容视图。

## 实现与验证

`renderer-git-sidebar.ts` 负责导航、列表和 Git 操作，`renderer-git-content.ts` 负责主区域正文的挂载、定位、并排对齐和合并编辑。Host 通过新增的 `git/content` RPC 返回基准、工作区与冲突阶段内容。

`tests/e2e/renderer-git-sidebar.spec.ts` 覆盖主区域边界、尺寸变化、差异、关闭重开、侧栏切换、提交后清理和卸载。
