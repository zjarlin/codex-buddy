# 会话完成待确认

Renderer 为官方 Codex 与外部 Harness Thread 维护统一的“待确认”队列。Turn 进入成功、失败或中断终态后，如果它不是当前可见会话，中央会显示轻量非模态卡片，展示最后一轮 `agentMessage` 或失败原因；用户可查看结果、直接在卡片输入框续发、标为已读或归档，也可以先关闭卡片继续当前工作。

## 状态与确认

- 队列记录 Host、Thread、Turn、终态、标题、摘要、完成时间及确认状态，并以 `codexhost.pending-confirmations.v1` 保存在本机 `localStorage`，应用重启后保留。
- 摘要保留最后一轮 `agentMessage` 的 Markdown 块结构：逐行去掉行尾空白、把连续空行压成一个空行，但**不把换行折叠成空格**。否则标题、列表、表格会塌成一段文字。超长时按原文截断，并补齐未闭合的代码围栏。卡片按块渲染标题、段落、嵌套列表、引用、代码块、GFM 表格（含对齐）与行内格式，排版与官方 Transcript 一致。
- 卡片面板按视口自适应放大（默认上限 880×820），摘要区占据正文剩余高度并单独滚动；因此长结果不再被旧的 240px 上限裁掉，输入框与底部操作始终可见。
- 同一 Turn 的重复完成通知幂等。同一 Thread 上的新 Turn 只有在用户此刻正看着该会话时才算接管旧待确认项；中断恢复、重连后的自动续跑、卡片续发都会在后台开新回合，旧提醒必须留到新回合真正出结果时再被替换，不能被新的 turnId 顶掉。已确认记录保留在有限队列中用于历史对账，不重新弹窗。
- **侧栏蓝点与完成卡片是同一份队列的两种投影，个数恒等**：队列里有几条待确认，侧栏就有几个补充蓝点，能弹出来的卡片就有几条（一次展开一条，其余显示数量）。没有待确认项就不补蓝点；官方蓝点已经表示同一条结果时不重复绘制。
- 当前可见 Thread 的 Turn 完成时只进入待确认，不弹卡片。弹窗摘要本身不算已读；点击“查看结果”并确认右侧已切换到目标会话后才视为读过（同时确认队列项与蓝点），在可见且聚焦的原会话连续停留 3 秒也会完成确认。关闭卡片同样按已读处理并持久化，因此重启后不会再弹同一条完成提醒。
- 卡片底部输入框复用当前 Host 的原生 `turn/start`（与 Composer、回合动作同一路径），把文本作为新的用户消息续发到该 Thread；官方 Thread 与外部 Harness Thread 共用这一条发送链路。发送成功后清空输入并关闭卡片，留在当前页面，不跳转到续发会话；失败时保留输入并提示重试。空文本不发送，Enter 发送、Shift+Enter 换行。
- “继续”按钮复用续发链路和所选模型，直接向卡片对应会话发送固定文本“继续,遇到决策你自己决定”，无需填写输入框，也不会发送输入框中的草稿；发送中禁用以避免重复提交。成功后关闭卡片并留在当前页面，失败时保留卡片与草稿并提示重试。“继续”不区分回合终态：正常完成、执行失败与已中断的会话都显示该按钮。
- “标为已读”只确认并保留会话；“归档”先调用现有 `thread/archive`，成功后才确认并移除；失败时保留待确认状态。关闭弹窗不会确认。
- 底部操作分两组：左侧是“查看结果”“标为已读”“归档”，右侧单独放“继续”，中间用分隔线与 24px 间距隔开；宽度不足时“继续”换到独立一行。这样想点“已读”时不会点到立刻发出续发消息的“继续”。
- 多个待确认项一次只展开一个，其余显示数量；侧栏“待确认”视图按 Host 与 Thread 隔离显示队列项。
- “查看结果”通过侧栏原生行切入会话。Desktop 的侧栏按项目分页，只渲染每个项目的前若干行，其余行折叠在折叠的项目头或“展开显示”加载更多控件之后；待确认会话常常正落在这批未渲染的行里。导航会先用 Host/Thread 身份或提醒记录中的项目显示名定位目标项目，并切换到该项目所属的项目 Tab；Thread 行尚未挂载时优先从同一 Host 的原生项目 `threadKeys` 成员关系识别归属（包括远端项目使用的 `local:` 成员键），其次补读 `thread/read` 的 `cwd` 与项目目录精确匹配，再使用唯一显示名。身份冲突或仍无法识别时保留当前 Tab 并报告打开失败，待确认项保留，不切到“全部”扫描。明确的目标项目尚未挂载时等待其出现，不退回展开整个侧栏。随后只展开目标项目、只节流点击该项目内通过 Fiber 暴露 `hasMoreItems && onExpandedChange` 分页契约的“展开显示”控件，把目标行挂载出来再点击；否则一次行查询就会超时报“无法打开该会话”。点击按轮次限流，避免原生列表反复重渲染时把 App server 请求队列打满。打开成功后保留目标项目展开，让目标行继续可见并参与侧栏滚动聚焦；为探测其他项目而临时展开的状态会在成功、超时或取消后还原，避免整个左侧树被点开后残留。

## 回到刚才的会话

点“查看结果”会把用户带到已完成的会话，原本正在看的会话随之丢失，而侧栏里常常记不住是哪一个。因此跳转前会记录来源会话（与卡片同一份 `activeThread` 判定），跳转后左下角出现一个轻量胶囊，标注“回到刚才的会话”和来源会话标题；点击即按同一原生侧栏行入口切回来源会话。

- 入口只保存一份来源会话，按 Host 与原生会话 ID 隔离；来源与目标相同（例如会话完成时用户正看着它）时不显示入口。
- 用户自己走回来源会话、点击返回、点击胶囊右侧关闭按钮都会收起入口；返回失败（行未渲染或导航被取消）时保留入口，用户可重试或从侧栏自行切换。
- 入口只做导航，不写入会话历史、不改原生侧栏属性、不新增 Host 协议。

## 重启对账

每次连接建立后，Renderer 只按侧栏行当前的原生未读状态对账：

- 官方仍标未读、队列里又没有的 Thread，读取其最新 Turn 后补入待确认队列，使蓝点与卡片继续一一对应。
- 上次启动遗留、但官方已经读过、且当前不在执行中的待确认项就地确认（转入 `confirmed`），蓝点与卡片一起消失，不会在下次启动再弹。
- 会话重新进入执行态（中断续跑、重连恢复）时侧栏只表示“还没出结果”，`unread=false` 不算用户已读：卡片保持待确认，直到回合真的回到 idle 且官方未读消失才确认。
- 不再扫描全部近期历史终态；只有官方仍标未读的会话才补入，避免把用户早已读过的记录重新做成待确认项。
- 同一 Turn 无论是否确认过都不会被复活；该 Host 的侧栏行尚未渲染时本轮对账跳过，等下一次刷新重试。

另一个窗口确认或归档后，本窗口通过 `storage` 事件重新读取队列，不会用旧内存快照把已读状态覆盖回待确认。

## 语音播报

待确认卡片右上角、关闭按钮左侧的小喇叭用于手动重播最后一轮结果摘要（`POST /media/tts`，由 Host 复用 Codex 网关凭据调用，使用 `return_base64: true` 返回 base64 WAV）。媒体入口位于网关根路径，不继承模型接口的 `/v1` 前缀。底部操作从左到右为「查看结果」「继续」「标为已读」「归档」，对所有终态一致。播报不写入原生历史、不进入工具链，也不改变待确认状态机。

- 「外观」页的自动播报开关默认关闭，仅保存在本机 `localStorage`（`codexhost.speech-announcement.v2`）。升级时不继承旧版默认开启的 v1 记录；用户可以重新主动开启。关闭只影响自动播报，不影响小喇叭手动重播。
- 若主动开启，只有应用处于前台且完成的是非当前会话（且不是标题生成回合）时才自动播报。合成返回时再次检查开关、可见性与焦点；窗口失焦或隐藏会取消尚未返回的自动播报并停止正在播放的自动音频，避免切换窗口后继续抢播。后台完成仍保留侧栏蓝点与待确认数量。
- 摘要先剥离 Markdown 与代码块，再截断到上限后合成。手动合成期间小喇叭禁用并提示「正在合成语音…」；合成或播放失败会在卡片显示原因，随后恢复按钮供重试。自动播报失败只写诊断，不影响完成提醒本身。
- 手动重播不受自动开关限制。同一窗口的新请求会立即停止此前音频，并丢弃旧请求迟到的合成结果；不同窗口的手动播放没有全局互斥。
- 网关地址与认证来自处理合成请求的 Host 的 `CODEX_HOME`（默认 `~/.codex`）配置，沿用当前 Provider 的认证规则：显式 Authorization、配置环境变量或 `provider.auth.command` 等；普通 API Key 配置读取 `auth.json`。不要求另填曼波 API Key，凭据只在 Host 内读取，不传给 Renderer。
- SSH 会话优先使用远端的播报能力；只有远端明确返回方法不存在时，才使用本机 Desktop Host 的 Codex 网关配置合成。该方法缺失按连接缓存，后续重播直接使用本机；远端隐私模式、网关错误或网络故障仍直接报错，不切换 Host。SSH 连接在合成期间替换或断开时丢弃本机返回的旧结果。

## 提醒边界

Codex 为 Thread 生成标题时会在后台的 ephemeral Thread 里跑一个内部 Turn，其唯一 `agentMessage` 是 `{"title","description"}` 形状的 JSON。这类 Turn 属于内部维护而非用户发起的工作，不会进入待确认队列，也不弹卡片。模型偶尔不按 JSON 返回，而是按提示词里的字段名回两行 `Title: …` / `Description: …`；这两种形状都按标题生成元数据过滤，读取旧队列时也会丢弃已经存入的同类记录。

标题生成的 ephemeral Thread 没有 rollout 文件、不出现在 `thread/list`、也没有侧栏行，因此一旦把它的回合终态当成用户会话提醒，用户就会看到“会话已完成”卡片却永远定位不到任何会话。Renderer 在通知订阅里同时监听 `thread/started`：`thread.ephemeral === true` 的 Thread 记入本连接的 ephemeral 集合，其 `turn/started` / `turn/completed` 一律跳过，既不进入待确认队列也不触发语音播报；集合按连接维护并设上限，避免长会话无限累积。内容识别（`{"title","description"}` JSON 或 `Title:` / `Description:` 两行文本）继续覆盖重启对账路径；卡片入队后还会按 `thread/read` 返回的 `ephemeral` / `threadSource=thread_title` 兜底撤回，几条路径互为补充。

当前提醒只发生在应用内：前台非当前会话完成时弹卡片，后台或最小化时保留侧栏蓝点和待确认数量，返回应用后再次显示。没有新增 Rust、系统通知或平台权限桥；侧栏原生未读状态语义保持不变，补充蓝点是待确认队列的投影，与卡片一一对应。

## 实现位置

- `packages/renderer-extension/src/pending-confirmations-state.ts`：队列归一化、摘要、幂等、确认和持久化。
- `packages/renderer-extension/src/renderer-pending-confirmations.ts`：通知订阅、弹窗、阅读计时、归档和重启对账。
- `packages/renderer-extension/src/markdown-renderer.ts`：轻量 Markdown 分块渲染器，被待确认卡片摘要使用。
- `packages/renderer-extension/src/renderer-thread-return.ts`：记录来源会话并在跳转后提供返回入口。
- `packages/renderer-extension/src/renderer-sidebar-unread.ts`：待确认项的侧栏补充蓝点。
- `packages/renderer-extension/src/renderer-sidebar-status-filter.ts`：全部、进行中、待确认三种侧栏视图。
- `packages/renderer-extension/src/renderer-speech.ts`：完成摘要清洗、网关合成调用与单条音频播放。
- `packages/renderer-extension/src/renderer-speech-preference.ts`：默认关闭的自动播报开关与变更事件。
- `packages/host-runtime/src/buddy/speech.ts`：曼波 TTS 合成、语种映射与音频上限校验。

完成提醒在会话标题上方显示 Host 与项目面包屑。优先使用原生侧栏项目标签，其次使用会话工作目录；旧提醒通过 `thread/read` 补齐项目，不借用当前打开会话的项目。侧栏分页控件尚未异步挂载时持续检查，默认最多等待 15 秒；分页点击仍限流并有轮次上限。

## 共用卡片外壳

完成卡片与[会话定时提醒](thread-reminders.md)共用 `notification-card` 提供的非模态外壳（遮罩、居中面板、标题行、正文区、提示行与操作栏），因此两者在尺寸、层级、响应式断点和焦点样式上保持一致。

外壳只负责结构与通用样式；完成提醒保留自己的队列语义、Markdown 摘要、续发输入框、语音重播和底部操作分组，定时提醒保留自己的到期调度与“打开会话 / 稍后 / 知道了”动作。改动其中一方的边框、间距或面板尺寸时会同时影响另一方，需要一起回归两个 E2E。
