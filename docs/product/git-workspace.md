# Git 工作区界面

左侧导航第二项为“提交”。侧栏保留分支信息、提交消息与操作区、变更／已暂存文件列表；文件和目录行高为 24px。提交消息位于文件列表上方。不提供独立 Git 日志入口。

面板顶部显示当前聊天对应的项目目录名，悬停显示完整路径。项目由当前可见的主对话 Composer 与当前 Host 确定，Host 再按任务 ID 解析工作区；不使用侧栏列表中其他任务的项目。切换任务或 Host 时立即切换到对应缓存快照并清空旧提交草稿，读取该任务的状态和模型目录。没有激活任务时显示“未选择项目”。

状态、差异、模型目录和 AI 提交消息只更新发起请求时的任务与 Host。旧项目的延迟结果不会覆盖新项目；在暂存与提交之间切换聊天时，不继续发起旧项目的提交。

## 加载与缓存

- 目录树默认折叠，点击目录才创建子项。进入面板不自动读取或打开首个文件差异。
- 激活聊天后延迟 250ms 预热 Git 状态；只预热当前任务，不批量读取文件正文。
- 状态、模型目录和已打开的差异按 Host 客户端与任务隔离缓存 30 秒，并合并进行中的相同请求。再次进入先显示已有状态，过期后刷新。缓存仅保留在当前 Desktop 进程中，最多 48 项、约 16 MiB。
- 暂存、取消暂存、提交和推送直接使用操作返回的新状态，避免重复查询。写操作清理该 Host 的旧快照和正文缓存；推送后关闭正文并折叠目录。手动刷新强制重新读取。
- 仅忙碌状态或选中文件变化时复用现有列表节点；正文默认统一差异。并排对齐按需计算，设置计算时限，只渲染滚动位置附近的 100 行，长行可悬停查看或切换“结果”。
- 刷新、暂存、提交、推送、同步、子模块操作、生成消息以及正文保存／暂存显示按钮 loading 和 `aria-busy`，请求结束前禁用冲突操作。操作锁按 Host 客户端与任务保存，切换聊天再返回仍保持；成功或失败后释放，失败可重试。
- Host 将同一工作区、同一参数的进行中写请求合并为一次执行。该保护只覆盖重叠请求，不把已完成请求永久缓存为成功。
- Git 索引中的子模块缺少 `.gitmodules` 映射时，面板单独显示配置警告，仍返回文件状态、有效子模块和暂存／提交／推送结果；不自动修改仓库配置。其他 Git 错误正常报告。

## 提交、推送与拉取同步

- 操作区提供“提交”“提交并推送”“推送”“拉取并同步”。提交消息可由所选模型根据真实改动生成，生成后仍可编辑。
- “拉取并同步”先 `fetch` 再按落后情况合入：本地无独有提交时快进，否则以 merge 合入上游，默认不变基。远端没有新提交时提示已是最新。
- 推送被远端拒绝（non-fast-forward）时，Host 回带结构化 `push-rejected` 错误和落后提交数，界面提示改用“拉取并同步”，不强制推送。
- 同步产生冲突时，`git/status` 返回 `operation` 与 `conflicts`。侧栏顶部的冲突横幅列出待解决文件，并提供“解决并继续”“中止合并”；仍在冲突中的文件不计入可提交变更。
- 冲突消解由模型回合完成（见 [Buddy Auto Router](buddy-auto-router.md) 的 Git 工作流），侧栏只负责展示状态、继续或中止，不自动合并冲突内容。

## 主区域内容

- 选择变更文件后，差异正文占用聊天区域。侧栏文件列表保持可操作。
- 文件正文支持“统一”“并排”“结果”三种视图。并排视图左栏显示基准版本，右栏显示当前工作区；对比块左侧的采纳按钮会把该行应用到结果版本。
- 结果视图允许直接编辑并保存回工作区；保存使用文件打开时的版本校验，文件被其他程序改动时拒绝覆盖。
- 保存以点击时的内容为准；等待保存时继续编辑的内容仍标记为未保存。切换文件后，旧保存结果不会覆盖新文件。
- 冲突文件显示 BASE、当前和传入版本，可直接采用当前或传入内容，再编辑后保存。冲突未解决前不能从正文暂存。
- 内容视图跟随原生主对话表面的位置与大小，避开顶部栏、侧栏和已展开的底部面板。找不到主对话表面时隐藏正文。
- 点击关闭按钮或按 Esc 返回聊天；切换到项目或文件浏览器也会关闭 Git 正文。聊天 DOM 与会话状态保留。
- 成功提交后关闭旧差异；关闭、切换文件或切换会话后，过期的异步差异不会重新打开内容视图。

## 实现与验证

`renderer-git-sidebar.ts` 负责导航、列表和 Git 操作，`renderer-git-content.ts` 负责主区域正文的挂载、定位、并排对齐和合并编辑。Host 通过新增的 `git/content` RPC 返回基准、工作区与冲突阶段内容。

Host 在 `git-workspace.ts` 提供 `git/fetch`、`git/sync`、`git/merge/continue`、`git/merge/abort` 与结构化推送拒绝；`git/sync` 默认以 merge 合入上游并在冲突时保留合并态，冲突内容交由模型回合消解。

`tests/e2e/renderer-git-sidebar.spec.ts` 覆盖主区域边界、尺寸变化、差异、关闭重开、侧栏切换、提交后清理、拉取同步与合并冲突横幅。

## 项目推送工作流

聊天输入框附近的“推送代码”按钮触发当前项目的提交并推送工作流，保留输入草稿。按钮显示等待、准备、运行、完成或失败状态；请求期间显示 loading，禁止重复点击。工作流沿用触发任务，在原对话中展示 Git 操作和结果，不新建任务。

默认监听 Host 的真实回合结束事件：原生 Codex `turn/completed` 和外部 Harness 的成功终态都可触发。等待 750ms 后，按 Git 工作树根目录（解析符号链接）汇总同一项目的任务；子目录聊天归到同一工作树，不同 worktree 分开处理。运行回合、等待审批、启动中的请求、规划、子任务和自动续接都阻止该项目启动推送；其他项目仍可继续运行。没有新改动且本地已同步时直接跳过。

同一 Host 服务的 Desktop 与远程客户端共享工作区锁和终态去重；启动前分页检查原生任务列表，并汇总各连接的外部任务。自动 hook 与手动按钮共用入口，同一项目只启动一次。模型准备期间若有新任务开始，回到等待状态；推送期间其他任务完成时，合并成一次后续检查，待当前工作流结束且项目空闲后处理。手动点击时项目仍忙也会等待，无需再次点击。

官方 Codex 使用当前可用的 Git 执行模型与已启用的 Git／GitHub／GitLab／PR 技能，跳过意图分类和高级模型规划；外部 Harness 沿用其原生会话配置。工作流生成提交消息、提交项目改动并推送；推送被拒时按既有 Git 工作流 fetch／merge、解决冲突、验证并重试。原生权限与审批保留，隐私模式和已知的 Plan Mode 不执行该工作流。

只对正常完成的任务新增自动请求。失败或取消不新增请求；已有等待请求会在其他任务结束后重新检查。工作流自己的终态不再次触发推送。完成后还检查 Git 工作区、上游和 ahead 状态；未同步时显示失败，可手动重试，不以模型回合正常结束代替 Git 验收。Host 启动、历史回放及只读状态检查不会补跑推送。

`CODEXHOST_GIT_AUTO_PUSH=0` 可关闭结束 hook，保留手动按钮。状态与锁保留在当前 Host 服务进程内，重启不恢复未执行的等待请求。按钮状态轮询只读取内存快照；原生任务扫描与 Git 检查在工作流触发时进行。
