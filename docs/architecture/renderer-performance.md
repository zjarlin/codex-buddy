# Renderer 注入层性能

性能优化范围是 `packages/renderer-extension`。官方 Desktop 的 React 渲染、历史加载与 Electron 基础开销不由 Host 接管；这里约束的是注入代码在消息流、DOM 变化和后台轮询中增加的工作。

## DOM 观察与扫描

- Composer 绑定只响应输入区、会话标识、标题栏和导航栏的相关变化。初次安装同步绑定，后续扫描按动画帧合并；Host 路由事件显式刷新绑定目标。发送前的身份与路由校验仍然执行。
- `renderer-dom-mutations.ts` 只检查变更节点、祖先和变更子树。普通消息文字和无关消息元素不触发 Composer、侧栏行、项目菜单或 Git 面板的全页扫描。
- 侧栏图标、聊天操作和续接按钮只响应侧栏行变化。行清理使用集合查询；控件属性只在值改变时写入。
- Git 侧栏在挂载关系仍有效时复用原锚点。差异面板通过尺寸观察处理布局变化，文档观察只处理主区域和标题栏的结构替换。
- 自动滚动在每个消息滚动区域内观察文本变化，每帧最多滚动一次。文档观察只发现滚动区域的增删；用户上翻后仍暂停跟随，新聊天绑定独立滚动状态。

不要重新给文档根节点添加 `characterData` 观察，也不要让普通消息追加触发全局 `querySelectorAll`。缩小观察范围时必须保留容器替换、Host 切换、迟到的会话标识与卸载清理。

## 轮询与渲染

`renderer-visible-poll.ts` 统一管理需要周期读取的控件：没有消费者时不创建定时器；文档隐藏时取消定时器；恢复可见时立即补读，并恢复原刷新间隔。安装发生在隐藏窗口时，也必须先登记消费者，确保恢复可见后能读取。

| 消费者 | 可见且有效时的周期 | 激活条件 |
| --- | --- | --- |
| Auto Router | 1.2 秒 | 当前 Composer 有适用的上下文 |
| Git 工作流 | 1.5 秒 | 当前 Composer 有适用的上下文 |
| 项目同步 | 2 秒 | 面板激活或设置页挂载 |
| 侧栏续接状态 | 15 秒 | 侧栏存在已识别的 Host |

侧栏续接不再每 1.5 秒重新扫描全部行；DOM 变化负责重绑行，状态轮询直接读取已知 Host，沿用原有 15 秒数据有效期。焦点和路由变化仍可主动刷新。

Auto Router 只根据设置、模型目录、JEV 配置状态、当前聊天决策和语言判断是否重绘。其他聊天决策或相同快照不会重建当前设置控件。Git 工作流也跳过相同展示状态的 DOM 写入。异步读取保留并发保护和过期响应检查；项目同步设置页的定时读取不会互相重叠。语言切换会销毁旧的 System One 标题控件。

## 性能回归与证据边界

`tests/e2e/renderer-binding-startup.spec.ts` 使用真实注入模块、2,000 条历史消息和 30 批异步消息元素追加，检查以下全页查询次数为零，并输出 `streaming-document-queries` 附件：

- Composer 编辑器查找；
- 侧栏聊天行查找；
- 原生按钮查找；
- 项目菜单项查找。

同一压力场景在区域过滤前触发了 30 次 Composer 全页扫描。该结果说明消息追加不再唤醒这些无关扫描，不代表整个 Desktop 零开销，也不能换算成 CPU、内存或帧率的提升百分比。

滚动测试覆盖直接文本更新、多个消息子树、容器替换、手动上翻与跟随恢复。Auto Router 测试覆盖重复读取、其他聊天更新时保留输入、隐藏窗口安装后恢复，以及上下文移除后的轮询停止。轮询单元测试覆盖激活、可见性、销毁和定时器释放。

可按 `package.json` 的 `test:e2e` 脚本运行对应测试。`CODEXHOST_PLAYWRIGHT_EXECUTABLE_PATH` 可指定本机 Chromium 兼容浏览器。源码测试和 `build:renderer` 构建结果不代表已安装客户端已加载新代码；实际 CPU、内存和输入延迟需要在更新产物后，以相同聊天和输出负载另行对比。
