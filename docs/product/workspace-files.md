# 工作区文件浏览与编辑

## 当前行为

左侧“文件浏览器”入口转发 Codex Desktop 官方文件树。优先点击已存在的官方文件树按钮；没有可定位按钮时转发 `run-command / toggleFileTreePanel`。整个文件／审查区域位于对话区左侧，包含标签栏、文件树和文件内容。横向顺序是「项目／会话列表 → 官方文件区域 → 对话区」；文件区域内部继续按「文件树 → 内容或差异」排列。

首次激活官方文件或审查标签时，扩展读取该标签原生菜单的 `unified-workspace-move-left`（移到左侧窗格）动作并调用。官方布局状态负责整个内容面板的位置、标题栏、宽度、分隔条和持久化；菜单确认已在左侧后不再反复执行，用户后续手动调整位置仍有效。浏览器、终端及底部面板不主动触发移动；官方内容标签共享同一窗格，因此同组其他标签沿用该窗格位置。菜单异步返回时重新校验当前标签，切换会话或卸载后不执行过期动作；不支持此菜单动作的版本保留原生布局。

Renderer 通过已提交的 React 祖先确认官方文件树及其尺寸回调，只调整原生节点的 CSS 排序、分隔线和拖拽边界，不移动或复制 DOM。拖动右边界时调用当前原生 `setSize`，保留官方宽度限制、折叠和持久化行为；双击恢复宽度仍由原生处理。新标签中的文件树同样应用左侧布局，扩展卸载时恢复原生样式。无法确认绑定的版本保持官方布局。

扩展不再维护第二份文件树、CodeMirror 编辑器或文件草稿，不将官方私有组件移出原生 React 树。当前 Thread 与 Host 由官方工作区状态提供，文件内容由官方文件服务读取；扩展不为打开文件树调用 codexhost 的文件 RPC，也不会把远程路径交给本机文件系统读取。

Git 审查入口同样复用官方面板，数据归属和原生恢复契约见 [Git 工作区界面](git-workspace.md)。文件浏览入口使用会话项目，不跟随提交侧栏的关联仓库选择。

## Host 文件接口

以下接口保留给其他调用方；其约束不代表官方编辑器的能力或限制：

- `codexhost/workspace/files/list` 按目录列出一层内容，上限 5000 项。
- `codexhost/workspace/files/read` 读取单个文件并返回基于 SHA-256 的 `revision`。
- `codexhost/workspace/files/write` 写入已有文本文件，要求 `expectedRevision` 与当前内容一致。冲突时拒绝覆盖；保存使用同目录临时文件与原子替换，保留文件权限。

Host 将路径解释为工作区内的 POSIX 相对路径，拒绝绝对路径、空路径段和 `..` 越级。访问前校验真实路径，防止符号链接逃逸。读取和写入最多 1 MiB，二进制文件与截断内容不能通过该写接口保存。

## 验证边界

Renderer 浏览器夹具包含项目列表、完整文件区域及对话区，验证文件内容与标签栏都位于对话区左侧、官方菜单动作调用、非文件面板排除、异步菜单过期保护、原生节点与打开文件回调保留、缩放后的拖拽方向、双击恢复、折叠重开和卸载清理。入口测试验证不再创建自绘文件面板或读取其正文。布局绑定依据 Desktop 26.924.22138 的官方标签菜单、文件树结构和尺寸回调。Host 单测继续验证文件接口的排序、路径安全、二进制与截断识别、revision 和冲突保护。

真实 Desktop 的文件树打开、文件编辑与保存需在对应安装版本验证；浏览器夹具不模拟或证明官方编辑器内部行为。
