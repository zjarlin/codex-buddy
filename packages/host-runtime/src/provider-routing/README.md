# 多供应商接续

`routing.ts` 属于每个官方运行时 Scope，统一接入本地、远程和直连启动路径。原生供应商身份与认证保持不变，仅在启动参数中把自定义 Responses 供应商指向带随机访问令牌的本机代理。配置中的原始端点不被覆盖。

`store.ts` 原子保存备用顺序、启用状态和独立密钥，兼容读取旧应急供应商。`proxy.ts` 在无响应内容时切换故障上游；部分流中断只终止响应并冷却该上游，由 Codex 原生机制决定重试，绝不自行重放工具或重新发送用户消息。代理不提供跨供应商服务端响应 ID 翻译。

会话级 `select` 由 Host 验证原生 Thread 所属供应商后写入 `threadProviders`；`null` 表示恢复自动。代理从官方 `session_id` 或 Turn 元数据解析 Thread，显式选择仅影响该 Thread 的下一次请求，使用目标供应商的独立密钥与模型。显式选择不受自动接续开关约束，也不在失败时切到其他供应商。携带私有响应 ID 的跨上游请求返回 409；未接入代理的原生 SSH 连接无法通过本机配置获得此能力。
