# 团队用量（局域网成员汇总）

“团队用量”页把同一局域网内多台 Codex Buddy 的用量按成员、部门和项目汇总。每台 Host 仍只统计并计价自己机器上的原生会话，团队页只做汇总，不读取其他成员的会话内容。

## 计量口径

- 成员数字来自该成员 Host 自己的“用量统计”结果：同样的请求去重、同样的 Token 口径、同样的读取失败提示。团队页只接收按范围聚合后的投影，不接收原始会话。
- 费用是**模型公开目录价（models.dev）的 API 等价估算**，与“用量统计”页完全一致：
  - 不是 sub2api 或其他网关的实际扣费，也不是订阅/套餐账单。
  - 因此会明显高于网关实付：一是按未打折的公开单价计算，二是缓存读取通常占输入的大头（本机 30 天样本约 89% 命中率），按目录价计费后这部分仍按缓存单价计入；而订阅或中转通常以极低或零单价处理缓存。
  - 需要真实账单价时，应在“模型价格”里为该模型设置自定义价格，汇总会按新价格重算。
- 某成员不可达时，其行仍然显示，数字为空并标明不可达；部门合计只加总上报了数字的成员。

## 配对与网络

- 每台 Host 在 `<数据目录>/team-usage/state.json` 保存设置与成员；稳定成员 ID 保存在同目录的 `id` 文件，重装设置不会让汇总方认错人。
- 监听端口默认 `45871`，可在页面上修改；开启后监听 `0.0.0.0`，成员地址由本机 IPv4 网卡地址拼出。修改端口会重启监听，页面立即显示新端口是否可用。
- 成员地址由汇总方在页面上填写（或从局域网发现取用），被读取方只记录请求来源用于识别，不会把它当成可回连的端点，也不会因为批准请求就向对方回推数据。
- 配对需要双方显式动作：
  1. 被读取方点击“生成配对码”，得到 8 位一次性码（5 分钟有效）。
  2. 汇总方在“局域网内发现”里选中该成员（或手动填 `地址:端口`），填入配对码发起配对。
  3. 被读取方在“等待批准”里通过后，双方各保存一份共享密钥；汇总方之后用该密钥拉取用量投影。
- 局域网发现走独立的 UDP 端口 `45872`，每 5 秒广播一次姓名、部门和端口；只用于填地址，不传用量。广播是未认证的，所以只显示为“发现”，不会自动成为已配对成员。
- 成员可以同时是汇总方：`direction` 区分“本机读取的成员”和“读取本机的成员”，两列表分开显示，同一个人不会因为双向配对被统计两次。移除其中一行只解除该方向的关系，不会顺带撤销另一方向。
- 汇总方把同一个人重新配对时，新成员行在对方批准前不会生效；对方拒绝或配对过期时，原有成员行与部门保持可用。
- 等待批准分两类：别人发来的请求可在本页批准或拒绝；“正在等待对方批准本机”的尝试只作提示，不会重复请求，也不会在对方拒绝后清掉原有成员与部门。
- 每个方向最多 200 个成员；发现列表最多保留 64 个、20 秒内有效。
- 配对与读取都走局域网明文 HTTP，只用于同一可信网段；跨网段或不可信网络不要开启。

## 页面与导出

- 时间范围：今天 / 7 天 / 30 天 / 90 天 / 全部，统一使用当前页面的时区换算日期。
- 卡片：费用、总 Token、缓存命中率；下方给出“X / Y 个成员上报了该范围”。
- 表格：按成员、按部门、部门 × 项目、按项目。占比条按费用计算；不可达成员在部门表中单独计数。
- “导出 Excel”生成真正的 `xlsx` 工作簿：
  - `Summary`：范围、时区、费用口径、成员数与总计。
  - `Members`、`By Department`、`By Project`：明细与汇总。
  - `Department x Project`：长表，一行一个部门/项目组合。
  - `Dept x Project cost`：交叉表，行是部门、列是项目、单元格是费用，并给出两轴合计，适合直接给部门负责人看。
  - `Member x Project`：精确到人的项目明细。
  - 所有数字都是数值单元格（带千分位/金额/百分比格式），可直接在 Excel 里求和与透视。
